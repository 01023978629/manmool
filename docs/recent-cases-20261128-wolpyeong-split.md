# 월평타운 두 세대 합친 사례 → 세대별 두 글로 나누기(11/26 작업, 2026-11-28)

대표 지시("월평동 월평타운 두 세대 앞·뒤 베란다, 세대 나눠서 올려줘")로 11/27 에 공개한 두 세대 합친 글
`wolpyeong-town-two-homes-veranda-rain-pipe-fitting-20261126`(PR #246)을 내리고, 세대마다 한 글씩 두 글로 바꾼다.
원고는 사례 작성 폴더의 세대별 비공개 초안(`published:false`)이고 이 PR 에서 `published` 만 `true` 로 바꿨다(새 검사가 글 객체 전체를 세대마다 `entryHash` 로 고정).
문구는 대표가 승인한 합친 글 원고를 세대별로 옮긴 것이고, 사진과 대표 확인 내용에 없는 사실은 넣지 않았다. 이 PR 은 검사 통과 뒤 대표의 병합(공개) 승인을 기다린다.

## 옛 주소(합친 글)

합친 글 주소는 11/27 부터 공개돼 있었다. 저장소에 공개 글을 내리고 옛 주소를 남기는 방식이 없어서 이 PR 에서 작게 만들었다.

- `scripts/post-redirects.json`: `{옛 slug: {to, also, since}}`. 지금 한 건 — 합친 글 → 첫 번째 세대 글(`also` 두 번째 세대 글).
- `scripts/prerender-posts.py`: 위 표대로 `posts/<옛 slug>.html` 을 만든다 — 검색 제외(`noindex, follow`), canonical 은 새 글, `meta refresh` 0초로 새 글 이동,
  두 새 글 링크와 사례 목록 링크만 있는 작은 쪽(스크립트·사진·옛 본문 없음). 목록·RSS·sitemap·누수 색인·구별 쪽에는 넣지 않는다.
  옛 slug 가 다시 공개 글이거나, 가리키는 글이 공개 글이 아니거나, slug 형식이 틀리면 생성을 멈춘다(`tests/test_prerender_posts.py` 에 시험 2개).
  예전처럼 site.json 에 없는 쪽을 지우는 정리는 그대로고, 표에 있는 옛 주소만 남긴다(CI 의 생성물 최신 검사도 그대로 통과).
- `scripts/ensure-site-integrity.mjs` ⓪(고아 글): 표에 있는 옛 주소 쪽은 고아 글로 보지 않는 대신, 검색 제외·새 글 canonical·바로 이동을 갖췄는지와
  옛 slug 가 공개 글이 아닌지·가리키는 글이 공개 글인지 본다(변이로 확인: noindex 를 빼면·표를 비우면·없는 글을 가리키면 실패).
- 합친 글의 사진 9장·축소본 18장(`assets/cases/wolpyeong-veranda-rain-pipe-20261126-*`)은 지금 어느 쪽에서도 쓰지 않지만, 검사가 요구하지 않아 그대로 두었다
  (지우려면 별도 PR — 새 두 글은 같은 바이트의 사본을 새 이름으로 쓴다).
