# 직원 포털 → 현장 시설접수 연결 보완

2026-09-08 · 로컬 후보 · 운영 배포 전

## 범위

- 서버의 `portalMe` 응답으로 확인한 단지 코드만 접수 URL에 전달한다.
- `requests.view`와 역할의 권한 상한을 모두 충족해야 링크를 표시한다.
- 최초 권한 확인 전, 로그아웃·만료·권한 거부 뒤에는 href와 단지 표시를 제거한다.
- 320/390/1280px에서 접수 → 대표 검토 → 현장 오더 → 진행상태 확인 순서를 안내한다.
- 긴 단지명은 원문을 줄바꿈하고 모바일 헤더를 단지명/계정 2행으로 배치한다.
  로그아웃 조작 영역은 최소 44px를 유지한다.
- 로그인 비밀번호·PIN·세션·이메일·사진을 URL에 전달하지 않는다.

## 인증과 운영 경계

직원 포털의 코드+이메일 로그인과 기존 시설접수의 PIN 인증은 별개다.
두 시스템의 단지 코드가 동일한지 운영자가 확인해야 한다. 자동 로그인·자동 접수·
포털 내부 작업지시와 현장 오더의 자동 동기화는 추가하지 않았다.
현장 앱에서는 대표가 접수를 확인·수락하고 작업을 연결한다.

실제 로그인·단지 매핑·접수·상태 전송의 전체 운영 검증은 별도로 필요하다.
운영 API/계정/권한/사진/접수 데이터와 서버 배포 설정은 변경하지 않았다.

## 검증

- 직원 포털 관련 37개 검사 전체 통과: 최종 단독 실행 70.695초, 재시도 없음, exit 0.
- 신규 시나리오 7개 포함: 검증 전 숨김, 확인한 단지 연결, 역할 제한,
  단지 변경·권한 거부·로그아웃·만료 후 연결 제거, 모바일 폭/터치 검사.
- 검증 전 링크 노출과 로그아웃 후 href 잔류를 의도적으로 넣으면
  `허용되지 않은 접수 URL이 DOM에 남았다` 단언으로 각각 실패한다.
- 헤더 변이 2종도 추가했다. flex 보완을 제거하면 전체 폭 1400px,
  모바일 2행 배치를 제거하면 헤더 높이 1628px를 탐지하여 각각 exit 1로 실패한다.
- 정상·긴 한글·긴 영문 단지명 × 3폭에서 원문 보존/전체 가로 폭/헤더 높이/
  계정·로그아웃 영역을 확인한다. 정상·긴 이름 화면 6개를 캡처했다.
- 소스 품질 검사 `ensure-*.mjs` 23개 및 `_site` 공개 허용목록 일치 통과.
- 최초 동시 검사에서는 37개 중 4개가 시간/화면 안정화 조건에서 실패했다.
  기존 제한 시간·단언을 완화하지 않고 단독 재검사하여 모두 통과했다.
- 별도 테스트 브라우저와 가상 자료를 사용했다. 실제 계정으로 접수하지 않았다.
