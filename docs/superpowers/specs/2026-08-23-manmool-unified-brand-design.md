# 만물인테리어·만물누수 통합 브랜드 디자인 명세

- 상태: 사용자 검토 대기
- 승인된 방향: 같은 브랜드, 다른 역할
- 대상: 만물인테리어 홈, 만물누수 홈, 블로그 목록, 정적 사례 글
- 기준 공개 주소: `https://01023978629.github.io/manmool/`

## 1. 목표

두 서비스가 서로 다른 업체처럼 보이지 않도록 로고, 글꼴, 간격, 버튼, 카드와
상담 동선을 하나의 브랜드 체계로 통일한다. 인테리어는 따뜻하고 생활감 있는
분위기를, 누수·배관은 정확하고 신속한 전문 서비스 분위기를 유지한다.

인테리어 페이지에서는 고객에게 의미가 없는 `n8n`, 자동화 노드, AI 운영 방식
설명을 제거한다. 기능의 기술 이름보다 `무엇을 확인할 수 있는지`와 `다음에 무엇을
하면 되는지`를 짧게 보여준다.

방문자는 어느 페이지에서든 다음 세 가지를 바로 구분할 수 있어야 한다.

1. 지금 보고 있는 서비스가 인테리어인지 누수·배관인지
2. 실제 작업 사례와 상담으로 이동하는 방법
3. 대표 전화 `010-2397-8629`

## 2. 변경하지 않는 것

- 견적, 상담 접수, 시뮬레이터, 사례 생성, 블로그 프리렌더 동작
- `data/site.json`의 실제 현장·견적·자재·비용 데이터
- 전자계약과 현장 앱 소스·설정·고객정보
- 기존 공개 URL과 검색엔진용 canonical, RSS, sitemap 구조
- 실제 사례 사진을 AI 이미지나 스톡 사진으로 대체하는 작업

이번 변경은 공개 화면의 표현 계층과 탐색 동선만 다룬다.

고객 화면의 제목·안내 문구를 바꾸기 위해 `data/site.json`의 `company.hours`,
`automation`, FAQ 등 표시용 문자열은 수정할 수 있다. 사례, 포트폴리오, 자재,
견적 계산값은 수정하지 않는다.

## 3. 공통 브랜드 체계

### 3.1 이름과 로고

- 공통 주 브랜드명은 `만물인테리어`로 표시한다.
- 공개 화면의 `Loop Agent` 보조 문구는 `인테리어·누수 전문`으로 교체한다.
- 서비스 전환부에는 `인테리어`와 `누수·배관`을 나란히 표시한다.
- 누수 화면도 별도 업체 로고를 만들지 않고 같은 로고에 `누수·배관` 표식을
  붙인다.

### 3.2 색상

공통 바탕과 글자색 위에 서비스별 강조색만 다르게 쓴다.

| 역할 | 값 | 용도 |
|---|---|---|
| 공통 잉크 | `#142536` | 제목, 주요 버튼, 내비게이션 |
| 공통 아이보리 | `#F7F3EC` | 페이지 배경 |
| 공통 흰색 | `#FFFFFF` | 카드와 밝은 영역 |
| 공통 선 | `#DED7CC` | 경계선과 구분선 |
| 인테리어 브론즈 | `#9A693A` | 장식, 서비스 표식, 보조 버튼 |
| 누수 청록 | `#087F98` | 누수 버튼과 상태 표식 |
| 누수 네이비 | `#071F32` | 누수 히어로 배경 |

흰 글자를 쓰는 채움 버튼은 접근성 대비가 확보되는 어두운 브론즈 또는 청록만
사용한다. 밝은 금색과 밝은 청록은 장식에만 쓴다.

### 3.3 글꼴과 형태

- 외부 폰트 다운로드 없이 현재 시스템 한글 글꼴 스택을 사용한다.
- 제목은 굵고 짧게, 본문은 한 줄 70자 안팎으로 제한한다.
- 공통 카드 모서리는 18px, 작은 카드와 버튼은 12px를 기본으로 한다.
- 그림자는 한 단계만 사용하고, 테두리와 여백으로 계층을 먼저 만든다.
- 장식 애니메이션은 200~300ms 안에서 끝내며 `prefers-reduced-motion`을 따른다.

## 4. 공통 구성요소

### 4.1 상단 내비게이션

모든 공개 페이지는 다음 순서의 공통 골격을 사용한다.

`로고 → 인테리어/누수·배관 전환 → 실제 사례 → 상담 → 전화`

- 현재 서비스는 색상과 `aria-current`로 표시한다.
- 데스크톱에서는 전화번호를 항상 노출한다.
- 모바일에서는 메뉴 버튼과 하단 상담 도크를 사용한다.
- 각 페이지의 세부 메뉴는 두 번째 줄을 추가하지 않고 본문 내부 바로가기로 둔다.

### 4.2 버튼과 카드

- 주요 행동은 페이지당 한 가지 채움 버튼만 사용한다.
- 전화는 항상 전화 연결, 누수는 `leak.html#leakInquiry`, 인테리어는
  `index.html#inquiry`로 연결한다.
- 모든 버튼은 모바일에서 최소 44×44px을 확보한다.
- 카드 사진 비율은 4:3으로 통일하고 `object-fit: cover`를 사용한다.
- 카드 제목은 최대 세 줄, 설명은 최대 세 줄로 제한하되 원문 자체는 삭제하지
  않는다.

### 4.3 모바일 상담 도크

공개 홈·블로그·사례 글에서 동일한 세 버튼을 사용한다.

`전화 | 누수 | 인테리어`

본문 마지막 요소와 겹치지 않도록 safe-area와 하단 여백을 함께 적용한다.

## 5. 인테리어 페이지 단순화

### 5.1 제거할 설명

- 공개 화면에서 `n8n`, 자동화 노드, 자동화 파이프라인, AI 운영자 설명을 제거한다.
- 현재의 6단계 파이프라인과 숫자 통계 카드를 함께 제거한다.
- `Loop Agent`, `AI 상담 24시간`, `AI ESTIMATOR`, `AI SIMULATOR`처럼 고객이
  기술을 이해해야 하는 표현을 사용하지 않는다.
- 같은 내용을 설명하는 예상견적·시뮬레이터 소개 문단을 반복하지 않는다.

### 5.2 유지할 기능과 고객용 이름

기능 자체는 유지하되 다음처럼 결과 중심으로 이름을 바꾼다.

| 현재 표현 | 변경 표현 |
|---|---|
| AI 예상견적 | 간편 예상견적 |
| AI 견적 상담 | 예상 범위 확인 |
| AI 인테리어 시뮬레이터 | 우리집 공사 범위 확인 |
| AI 추천 디자인 참고 시안 | 인테리어 디자인 참고 시안 |
| AI 상담 24시간 | 온라인 상담 24시간 |

디자인 이미지는 실제 완공 사진으로 오인되지 않도록 `디지털 참고 시안 · 실제 완공
사진 아님`이라는 짧은 고지를 목록 상단에 한 번 표시한다. 생성 방식에 대한 긴
설명은 제거하지만 실제 현장 사진과 참고 시안의 구분은 유지한다.

### 5.3 간단한 페이지 순서

인테리어 홈의 주요 구간은 아래 순서로 정리한다.

1. 첫 화면: 공사 범위와 상담 행동
2. 실제 현장 사진 3건
3. 인테리어 디자인 참고 시안
4. 간편 예상견적·우리집 공사 범위 확인
5. 상담부터 보증까지 4단계
6. 보증·A/S 근거
7. 상담 신청

관리 도구 설명, 중복된 숫자 통계, 비슷한 소개 문단은 이 순서에서 제외한다.
상단 메뉴도 `인테리어`, `누수·배관`, `실제 사례`, `진행 순서`, `상담`으로 줄인다.

## 6. 화면별 설계

### 6.1 만물인테리어 홈

- 따뜻한 실제 주거 사진과 어두운 오버레이는 유지한다.
- 첫 화면의 빈 흰색 상담 예시 창은 정적인 `상담부터 완료까지` 안내 패널로
  교체한다.
- 안내 패널은 `사진·요청 남기기 → 실측·범위 확인 → 견적·시공·보증 기록`의
  세 단계와 실제 공정 사진 작은 썸네일 한 장을 보여준다.
- 첫 행동은 `무료 1차 상담 신청`, 두 번째 행동은 `실제 공정 사진`으로 정리한다.
- 히어로 아래에는 `누수 긴급상담`, `인테리어 실측상담`, `실제 시공사례` 카드
  세 개를 같은 높이로 둔다.
- 기존 자동화 파이프라인 대신 `상담 → 실측·견적 → 시공 → 준공·보증` 네 단계만
  아이콘과 한 줄 설명으로 표시한다.

### 6.2 만물누수 홈

- 네이비·청록의 진단 분위기는 유지한다.
- 스캐너 그래픽은 보조 시각물로 축소하고, 실제 탐지 장비 또는 배관 작업 사진을
  같은 영역에 함께 표시한다.
- `누수 지점 미확인 시 탐지비 0원`, `착수 전 요금 확인`, `사실자료 정리 지원`을
  짧은 증거 표식으로 유지한다.
- 첫 행동은 `지금 바로 전화 상담`, 두 번째 행동은 `내 증상부터 확인`으로 둔다.
- 상단 로고와 버튼 형태는 인테리어 홈과 동일한 공통 구성요소를 쓴다.

### 6.3 블로그 목록

- 상단에 최신 대표 사례 한 건을 가로형 큰 카드로 보여준다.
- 그 아래에 `전체`, `누수·배관`, `방수·욕실`, `인테리어`, `공사안내` 필터를 둔다.
- 필터는 기존 `data/site.json`의 `category`와 `service`만 사용하며 새 데이터
  필드를 요구하지 않는다.
- JavaScript가 없어도 모든 글 링크가 정적 HTML에 남아 있어야 한다. 필터는
  점진적 향상으로만 작동한다.
- 첫 대표 이미지만 eager/high로 로딩하고 나머지는 lazy로 유지한다.

### 6.4 정적 사례 글

- 블로그와 같은 공통 상단 및 모바일 상담 도크를 사용한다.
- 카테고리·날짜·읽기 시간은 제목 위의 작은 메타 영역으로 정리한다.
- 본문 폭은 읽기 편한 760px 안팎으로 제한한다.
- 실제 현장 사진의 캡션과 대체 텍스트를 유지한다.
- 누수 글은 누수 상담, 일반 인테리어 글은 인테리어 상담으로 연결하는 기존
  `service` 판정을 보존한다.

## 7. 코드 구조와 데이터 흐름

### 7.1 스타일 경계

- 새 `css/brand-system.css`에 공통 토큰과 공통 구성요소를 둔다.
- `css/styles.css`는 인테리어·블로그용 화면 배치를 담당한다.
- `css/leak-theme.css`는 누수 전용 히어로와 섹션 표현만 담당한다.
- 같은 선택자를 세 파일에서 중복 정의하지 않는다.

### 7.2 정적 생성

`data/site.json → scripts/prerender-posts.py → blog.html + posts/*.html`

- 블로그와 사례 글의 공통 상단·필터용 마크업은 생성기에서 재현한다.
- 생성된 `posts/*.html`은 직접 수정하지 않는다.
- 기존 공개 allowlist 빌드와 서버 소스 차단 정책을 그대로 유지한다.

### 7.3 오류와 폴백

- 사진이 없으면 깨진 이미지 대신 서비스 색상 배경을 보여준다.
- JavaScript 로드 실패 시 정적 글 목록과 모든 상담 링크가 계속 동작한다.
- 긴 아파트명과 긴 한국어 제목이 카드 밖으로 넘치지 않아야 한다.
- 애니메이션을 끈 환경에서도 정보가 사라지지 않아야 한다.

변경 대상이 아니다.

## 9. 검증과 완료 조건

### 자동 검사

- 새 디자인 검사는 공통 로고, 서비스 전환, CTA 경로, 블로그 필터, 정적 폴백,
  이미지 로딩 속성, 모바일 도크와 캐시 버전을 확인한다.
- 인테리어 공개 화면에 `n8n`, `Loop Agent`, `AI 상담`, `AI ESTIMATOR`,
  `AI SIMULATOR`가 남아 있지 않은지 확인한다.
- 간편 예상견적과 우리집 공사 범위 확인 기능은 이름 변경 뒤에도 동일한 계산과
  상담 전달 동작을 유지해야 한다.
- 새 검사부터 실패하는 상태를 확인한 뒤 최소 구현으로 통과시킨다.
- 기존 `scripts/ensure-*.mjs` 15개와 사례 생성 검사를 모두 재실행한다.
- Pages 공개 산출물 검사에서 서버 소스·백업·임시파일 제외가 유지되어야 한다.

### 실제 브라우저 검사

- 폭 320, 390, 768, 1280, 1440px에서 가로 넘침이 없어야 한다.
- 메뉴, 히어로, 카드, 모바일 도크가 서로 겹치지 않아야 한다.
- 버튼 최소 높이 44px, 일반 글자 대비 4.5:1 이상을 확인한다.
- 첫 블로그 이미지만 eager/high이고 후속 이미지는 lazy여야 한다.
- 콘솔 오류와 깨진 내부 링크가 없어야 한다.

### 배포

- 격리 브랜치에서 커밋하고 PR로 검토한다.
- 사용자의 배포 승인을 받은 뒤에만 `main`에 병합한다.
- Pages 실행 성공 후 네 페이지(인테리어 홈, 누수 홈, 블로그, 대표 사례)를
  공개 주소에서 다시 확인한다.

## 10. 승인 범위 요약

이번 작업은 공통 브랜드 디자인, 인테리어·누수 홈의 첫 화면, 블로그 분류와 카드,
정적 사례 글의 읽기 경험, 공통 모바일 상담 도크를 한 번에 맞추는 작업이다.
인테리어 페이지에서는 n8n·AI 기술 설명과 중복 운영 통계를 제거하고 고객용 이름과
네 단계 진행 순서로 단순화한다. 새로운 서버, 로그인, 고객 데이터 전송, AI 이미지
생성은 포함하지 않는다.
