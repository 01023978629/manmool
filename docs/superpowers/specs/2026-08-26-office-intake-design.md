# 관리사무소 시설접수 연동 설계

> **대체됨:** 이 문자 전용 설계는 2026-08-26 승인된
> `2026-08-26-office-hyeonjang-integration-design.md`로 대체되었습니다.
> 공개 배포 전 새 설계의 인증·Apps Script·현장 웹 연동 구조에 맞게 기존 로컬 구현을 수정해야 합니다.

## 목적

기존 `office.html`의 관리사무소 대상 영업·상담 기능을 유지하면서, 입주민이 단지 시설보수 내용을 휴대전화 문자로 안전하게 전달할 수 있는 별도 접수 화면을 추가한다. ZIP의 `HOME DOC` 전체를 공개하지 않고, 실제 운영에 필요한 접수 흐름만 만물인테리어 브랜드와 현재 공개 사이트 구조에 맞게 구현한다.

## 결정 사항

- `office.html`은 관리사무소 소장·직원에게 협업 방식과 실제 사례를 보여 주는 공개 영업 페이지로 유지한다.
- 새 거래 화면은 루트의 `office-request.html`로 분리한다.
- `office.html` 상단에는 기존 `업무 문의`를 주 행동으로 유지하고, `입주민 시설보수 접수`를 보조 행동으로 추가한다.
- 서비스 소개와 보고자료 영역 사이에 `단지 전용 시설접수 창구` 소개 구역을 추가한다.
- 브랜드는 `만물인테리어 관리사무소 시설접수`로 통일한다. `HOME DOC`, `담당 문규`, `homedoc.co.kr` 표기는 사용하지 않는다.
- 공개 전화번호는 현재 사이트와 사용자가 확인한 `010-2397-8629`를 사용한다.
- ZIP의 운영관리, 관리사무소 대시보드, 기사용 화면, 영업 키트, 샘플 접수 데이터는 배포하지 않는다.
- 현장 배정·사진·작업완료 관리는 기존 `hyeonjang`의 책임으로 남긴다. 이번 변경에서는 두 저장소 간 자동 동기화를 만들지 않는다.

## 정보 구조

### 관리사무소 영업 페이지

`office.html`은 다음 순서를 유지한다.

1. 관리사무소 업무 협력 소개
2. 자주 필요한 보수 업무
3. 단지 전용 시설접수 창구 소개
4. 결재·설명용 보고자료
5. 접수부터 완료까지의 업무 흐름
6. 실제 작업 사례
7. 대표 전화·문자 상담

시설접수 소개 구역은 별도 플랫폼처럼 보이지 않게 현재 브랜드 디자인을 사용한다. `시설보수 접수 화면 열기` 버튼은 `office-request.html`로 이동하고, 관리사무소 제휴 문의는 기존 상담 영역으로 이동한다.

### 입주민 시설접수 페이지

`office-request.html`은 모바일 우선 단일 화면 흐름으로 구성한다.

- 단지명
- 동·호수
- 문제 유형: 누수, 배관·배수, 욕실·방수, 공용부 보수, 기타
- 발생 위치
- 증상 설명
- 신청자 이름
- 회신 전화번호
- 필수 개인정보 수집·이용 동의

페이지는 입력값을 서버, `localStorage`, `sessionStorage`, IndexedDB에 저장하지 않는다. 사용자가 `문자로 접수하기`를 누르면 입력값으로 문자 내용을 생성하고 휴대전화의 문자 작성 화면을 연다. 실제 전송은 사용자가 문자 앱에서 다시 확인하고 눌러야 한다.

사진 첨부 입력은 제공하지 않는다. 문자 앱 전환 후 같은 번호로 현장 사진을 추가 전송하도록 안내한다. 문자 앱 전환이 되지 않는 환경에서는 `접수 내용 복사`와 `대표에게 전화`를 제공한다.

## 데이터 흐름

1. 입주민이 브라우저 메모리에만 접수 내용을 입력한다.
2. 필수값과 개인정보 동의를 브라우저에서 검증한다.
3. 다음 형식의 문자 본문을 생성한다.

```text
[만물인테리어 관리사무소 시설접수]
단지: ...
동·호수: ...
문제 유형: ...
발생 위치: ...
증상: ...
신청자: ...
연락처: ...
```

4. `sms:01023978629` 링크로 문자 앱을 연다.
5. 입주민이 문자 앱에서 내용과 수신번호를 확인한 뒤 직접 전송한다.
6. 대표는 받은 내용을 확인하고 기존 현장 운영 절차로 등록한다.

자동 문자 발송, 외부 폼 서비스, 분석 픽셀, 고객 정보 API 전송은 이번 범위에 포함하지 않는다.

## 오류와 안전 처리

- 필수값이 없으면 첫 번째 누락 항목으로 이동하고 구체적인 오류 문구를 표시한다.
- 전화번호는 숫자 10~11자리만 허용하고 화면에는 하이픈을 넣어 표시한다.
- 개인정보 동의 전에는 문자 작성 버튼을 사용할 수 없다.
- 문자 앱 실행 여부는 웹에서 확정할 수 없으므로 `접수가 완료되었습니다`라고 표시하지 않는다.
- 문자 앱 실행 뒤에는 `문자 앱에서 전송 버튼을 눌러야 접수됩니다`라고 안내한다.
- 복사 기능이 실패하면 본문을 선택 가능한 읽기 전용 영역에 보여 준다.
- 접수 페이지는 검색 유입용 콘텐츠가 아니므로 `noindex,follow`를 적용한다.
- `noopener`, CSP 호환 구조, HTML 이스케이프를 적용하고 사용자 입력을 `innerHTML`에 넣지 않는다.

## 파일 경계

- `office.html`: 시설접수 버튼과 소개 구역만 담당한다.
- `office-request.html`: 접수 화면의 문서 구조와 접근성 레이블을 담당한다.
- `css/office-request.css`: 접수 화면 전용 반응형 스타일만 담당한다.
- `js/office-request.js`: 검증, 문자 본문 생성, SMS 링크, 복사 대체 동작을 담당한다.
- `privacy.html`: 문자 접수 시 성명·전화번호·단지명·동호수·증상 내용을 상담 회신과 현장 확인 목적으로 수집하며, 일반 상담과 같은 1년 보관 기준을 적용한다고 명시한다. 계약으로 이어지면 계약·세무 관련 법정 보관기간을 따른다. 문자 접수는 Web3Forms를 거치지 않고 대표 휴대전화로 직접 전달되며, 접수 페이지 브라우저에는 사본을 저장하지 않는다는 점도 구분한다.
- `scripts/build-pages-artifact.mjs`: 새 공개 페이지를 Pages 허용목록에 포함한다.
- `sitemap.xml`: 검색 비노출 페이지이므로 추가하지 않는다.
- `tests/office-intake.e2e.cjs`: 실제 브라우저의 모바일 동작과 전송 전 확인 경계를 검증한다.
- `scripts/ensure-office-intake.mjs`: 링크·전화번호·저장 금지·배포목록을 정적으로 검증한다.

## 테스트와 완료 기준

- `office.html`에서 `office-request.html`로 이동할 수 있다.
- 390px 화면에서 가로 넘침이 없고 주요 버튼 높이가 44px 이상이다.
- 필수값과 동의가 없으면 SMS 링크가 생성되지 않는다.
- 정상 입력 시 수신번호 `01023978629`와 모든 필드가 문자 본문에 들어간다.
- 문자 앱 실행만으로 접수 완료라고 표시하지 않는다.
- 고객 입력값을 웹 저장소나 네트워크로 보내지 않는다.
- 새 페이지가 Pages 산출물에는 포함되고 sitemap에는 포함되지 않는다.
- 기존 `scripts/ensure-*.mjs` 전체와 브랜드 브라우저 회귀검사가 통과한다.
- 로컬 미리보기에서 데스크톱과 390px 모바일 화면을 시각 점검한다.

## 배포 경계
