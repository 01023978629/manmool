# 마스터 로그인 지원 — 프런트 검증·인계

2026-09-08. 기존 직원 포털 연결 개선 후보 위에 추가한 로컬 변경이며 아직 공개 배포하지 않았다.

## 변경

- 로그인 창에서 직원 숫자 6자리와 마스터용 공백 없는 8~64자 영문·숫자·특수문자 입력 지원.
- 입력 원문 보존, 역할은 서버에서 판정. 프런트에서 마스터 계정으로 승격하는 기능 없음.
- 관리자 발급 창은 대상 역할에 맞는 형식을 안내하고 마스터→직원 변경 시 새 6자리 필수.
- 로그인은 `current-password`, 발급은 `new-password`. 앱 자체의 원문 저장은 금지하고
  브라우저 비밀번호 저장 여부는 사용자가 선택함을 안내한다.
- 세 화면의 공통 core 캐시 버전 갱신. 기존 시설접수 PIN과 단지 연결 흐름 유지.

## 검증

UI 검사는 별도 테스트 브라우저와 가짜 계정만 사용했다.
실제 계정 생성/비밀번호 입력/권한 변경/접수 자료 조회는 하지 않았다.

- 최종 전체 45/45 통과(101.089초): core 12, API 5, 설정 3, 화면 25.
- 첫 전체 44/45에서 기존 비용·보고 화면의 스크롤 중 클릭이 2초 제한을 초과했다.
  시간 제한·단언을 유지한 단독 재검사와 최종 전체 재실행 모두 통과했다.
- 비밀번호 trim·직원 역할 제한·강등 비밀번호 필수 보호를 각각 제거한 변이 3종 모두 실패 검출.
- 정적 검사 23개(허용목록 산출물 포함) 통과. 공개 산출물 483개 source/output 일치.
- 320/390/1280px 입력 폭 검증. 320/390px 빈 비밀번호 화면을 캡처해 직접 확인했다.
  실제 휴대폰 키보드/자동완성은 실기기에서 별도 확인해야 한다.
- 프런트/서버 교차 입력 규약 828/828 통과. 검사 뒤 추가 제품 변경 없음.

## 적용 경계

새 비밀번호는 독립 포털 Apps Script 백엔드 선행 배포가 필요하다.
`portalHealth.authPolicy=master-password-v1` 확인 후 이 프런트를 공개하고 계정 발급을 진행한다.
GitHub Pages 배포만으로 Google 서버나 계정이 바뀌지는 않는다.
마스터 계정의 실제 비밀번호 입력·확정은 사장님께 인계하며 실제 비밀번호를 문서화하지 않는다.
마스터는 사용자·권한 관리 역할이며 모든 단지의 업무 자료를 우회 열람하는 역할이 아니다.
