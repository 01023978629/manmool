# 문의 접수함 켜기 — 대표님용 한 장 안내

> 홈페이지 상담 문의를 **구글 시트에도 한 줄씩 남기고**, 승인·보류·거절을 기록하는 기능입니다.
> 켜도 **메일(Web3Forms)은 지금처럼 그대로 옵니다.** 접수함은 메일에 더해 "기록"이 하나 더 생기는 것입니다.
> 이 문서에는 비밀번호·주소 같은 **값을 적지 않습니다.** 값은 대표님 구글 계정 안에만 둡니다.
> 걸리는 시간: 처음 한 번 약 30분. 자세한 기술 설명은 `apps-script-lead-inbox/README.md` 에 있습니다.

## 지금 상태

- **2026-11-19 켰습니다.** 대표님 계정으로 서버를 배포했고(실행: 나, 액세스: 모든 사용자), 홈페이지 `data/config.json` 의 `inbox` 에 주소를 넣었습니다(PR #238).
- 남은 일은 6-3 시험 문의 한 건과 7 현장웹 연결입니다. 아래 1~5 는 다시 설치할 때를 위한 기록입니다.

## 1. 접수함 전용 구글 시트 만들기

1. 구글 드라이브에서 **새 스프레드시트**를 하나 만듭니다. 이름은 "만물 문의 접수함" 처럼 알아보기 쉽게.
2. 다른 시트(현장 자료·관리사무소 포털 등)를 다시 쓰지 마세요. 꼭 **새로** 만듭니다.
3. 주소창의 `/d/` 와 `/edit` 사이 긴 글자가 **시트 ID** 입니다. 3단계에서 씁니다.

## 2. 새 Apps Script 프로젝트에 파일 붙여넣기

1. script.google.com 에서 **새 프로젝트**를 만듭니다. (관리사무소 포털·사진 중계 프로젝트와 **다른, 새 프로젝트**)
2. 아래 세 파일을 같은 이름으로 만들어 내용을 통째로 붙여넣습니다.
   - `Code.gs` — 새 프로젝트에 처음부터 있는 파일입니다. 원래 있던 글은 지우고 붙여넣습니다.
   - `LeadInboxPure.gs` — 편집기 왼쪽 **파일 ＋ → 스크립트** 로 만들고 이름에 `LeadInboxPure` 만 칩니다(`.gs` 는 자동으로 붙습니다).
   - `appsscript.json` — 왼쪽 ⚙ **프로젝트 설정**에서 "appsscript.json 매니페스트 파일 표시"를 켜야 보입니다.

   파일 내용은 GitHub 에서 복사합니다(컴퓨터에 저장소를 받을 필요 없음). `https://github.com/01023978629/manmool/tree/main/apps-script-lead-inbox`
   에서 파일 이름을 눌러 연 뒤, 내용 오른쪽 위의 **복사 아이콘(Copy raw file)** 을 누르면 전체가 한 번에 복사됩니다.
3. 💾 저장합니다.

## 3. 스크립트 속성 넣기 (이름만 적습니다 — 값은 대표님만)

⚙ **프로젝트 설정 → 스크립트 속성 → 속성 추가**에서 아래 이름으로 넣습니다.

| 속성 이름 | 넣을 것 |
|---|---|
| `LEAD_INBOX_ENABLED` | 숫자 `1` (켜기) |
| `LEAD_INBOX_SHEET_ID` | 1단계에서 본 시트 ID |
| `LEAD_INBOX_SESSION_SECRET` | 아무도 못 맞힐 긴 글자 32자 이상, 띄어쓰기 없이 (비밀번호 생성기로 40자쯤) |
| `LEAD_INBOX_LOGIN_PEPPER` | 위와 **다른** 긴 글자 32자 이상, 띄어쓰기 없이 |
| `LEAD_INBOX_ADMIN_CODE` | 접수함에 들어갈 **관리 비밀번호** (**8~64자**, 띄어쓰기 없이). 대표님만 아는 값 |
| `LEAD_INBOX_NOTIFY_TO` | (선택) 새 문의 알림 메일을 받을 주소. 비워 두면 알림 없음 |

- 긴 글자 두 개(`…SECRET`·`…PEPPER`)는 **외울 필요가 없습니다.** 크롬·휴대폰의 '강력한 비밀번호 제안'이나 비밀번호 관리 앱의 생성기로 만들어 붙여넣고 끝입니다.
- 관리 비밀번호는 **64자를 넘기면 안 됩니다** — 서버·화면이 64자까지만 받아서, 더 길면 맞게 넣어도 로그인이 계속 실패하고 아래 잠금까지 걸립니다.
- 관리 비밀번호는 카톡·메모·문서·채팅 어디에도 적지 마세요. 저(Claude)에게도 알려 주지 않으셔도 됩니다.
- 비밀번호가 **5번 틀리면 15분 동안** 접수함 로그인이 잠깁니다(누가 틀렸든 모두 잠김).
- ⚠ **알고 켠 점:** 이 잠금은 사람마다가 아니라 접수함 전체에 걸리고, 잠긴 동안에는 맞는 비밀번호도 들어가지 못합니다.
  접수함을 켜면 웹 앱 주소가 홈페이지 설정에 공개되므로(손님 폼이 써야 해서), 누군가 일부러 15분마다 틀린 값을 5번씩 보내면
  대표님과 현장웹이 접수함에 계속 못 들어갈 수 있습니다. **손님 접수와 메일은 그대로 옵니다.**
  2026-11-19 에는 ① 이대로 켰습니다(막히면 메일로 처리). 실제로 막히는 일이 생기면 ② 손님용·관리자용 주소 나누기나 ③ 잠금 방식 바꾸기를
  저(Claude)에게 말씀해 주세요 — 둘 다 서버 코드를 고친 뒤 다시 배포합니다.

## 4. 시트 준비 한 번 실행

1. 편집기 왼쪽 파일 목록에서 **`Code.gs` 를 눌러 엽니다.** (함수 선택 칸에는 지금 열린 파일의 함수만 나옵니다.)
2. 편집기 위쪽 **함수 선택 칸**에서 `leadInboxSetup` 을 고르고 ▶ **실행**을 누릅니다.
3. "권한 검토" 창이 뜨면 대표님 계정을 고르고 **허용**합니다.
   - **'Google에서 확인하지 않은 앱'** 화면이 나오면(개인 Gmail 이면 보통 나옵니다) 왼쪽 아래 **고급** → **(프로젝트 이름)(으)로 이동(안전하지 않음)** → **허용**.
     대표님이 직접 만든 스크립트라 구글 심사를 받지 않았다는 뜻입니다. 이 단계에서 멈추지 마세요.
4. 시트에 `문의`·`이력`·`세션` 탭이 생기면 성공입니다. (매일 새벽 4시 보관기한 정리도 이때 함께 걸립니다.)

## 5. 웹 앱으로 배포

1. 오른쪽 위 **배포 → 새 배포** → 유형 ⚙ 에서 **웹 앱**.
2. **다음 사용자 인증정보로 실행: 나**, **액세스 권한이 있는 사용자: 모든 사용자**.
   - "모든 사용자"여야 손님 폼이 접수할 수 있습니다. 문의 목록은 관리 비밀번호 없이는 안 보입니다.
3. **배포**를 누르면 `https://script.google.com/macros/s/…/exec` 로 끝나는 **웹 앱 주소**가 나옵니다. 복사합니다.

## 6. 주소를 Claude 에게 → 홈페이지에 연결 (제가 합니다)

1. 웹 앱 주소를 저에게 주세요. (주소는 비밀번호가 아닙니다. 관리 비밀번호는 주지 마세요.)
2. 제가 `data/config.json` 의 `inbox` 를 켜고 주소를 넣어 **PR** 로 올립니다. 대표님이 병합하시면 그때부터 폼 문의가 메일 + 접수함 두 곳으로 갑니다.
3. 병합 뒤 대표님이 홈페이지 상담 폼에서 **시험 문의를 한 건** 넣어 주세요(실제 메일도 한 통 갑니다).
   `lead-inbox.html` 에 관리 비밀번호로 들어가 그 문의가 보이면 성공입니다. 시험 건은 **거절**(사유: 시험)로 정리하세요.

## 7. 현장웹에서도 보기

- 현장웹 쪽 연결 작업이 들어간 뒤, 현장웹 설정의 **문의 접수함 주소** 칸에 **같은 웹 앱 주소**를 넣고 관리 비밀번호로 로그인합니다.
  (정확한 메뉴 이름은 현장웹 작업이 끝나면 따로 알려 드립니다.)
- 관리 비밀번호는 현장웹에도 **저장하지 않습니다.** 로그인은 8시간 유지되고, 끝나면 다시 넣습니다.

## 되돌리는 법

- **잠깐 끄기(가장 빠름)**: Apps Script 프로젝트 → ⚙ 스크립트 속성에서 `LEAD_INBOX_ENABLED` 를 `0` 으로 바꿉니다.
  접수함이 새 문의·로그인을 받지 않고, 홈페이지 폼은 **메일만으로 그대로** 동작합니다. 다시 `1` 로 바꾸면 켜집니다.
- **완전히 끄기**: 저에게 "접수함 꺼줘"라고 하시면 `data/config.json` 의 `inbox` 를 꺼짐·빈 주소로 되돌리는 PR 을 올립니다.
  병합하면 홈페이지가 접수함 주소를 아예 부르지 않습니다. 이어서 Apps Script **배포 관리**에서 그 배포를 **보관 처리**하면 주소도 닫힙니다.
- 시트에 남은 문의는 처리방침 기한(거절 90일·승인 1년)대로 정리됩니다. 시트를 지우는 것은 대표님 판단입니다(지우면 되살릴 수 없습니다).
- 코드를 고친 뒤에는 **배포 → 배포 관리 → ✏ 편집 → 버전: 새 버전**으로 다시 배포해야 반영됩니다. 주소는 바뀌지 않습니다.
