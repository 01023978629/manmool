```js
// js/main.js:344  portfolioPhotoStyle()
photo + photoPosition + photoScale + photoMirror
```

## 1. 할 일 A — 남은 59건에 크롭 지정

### 방법

`data/site.json` 의 해당 시안에 세 필드를 더한다. 이미 쓰이고 있는 값의 범위를 벗어나지 마라.

```json
{
  "id": "design-20260723-catalog110-minimal-05",
  "photo": "assets/designs/arch-entry-24.jpg?v=20260728-recrop-01",
  "photoPosition": "35% 50%",
  "photoScale": 1.05,
  "photoMirror": false
}
```

| 필드 | 쓰이고 있는 값 | 주의 |
|---|---|---|
| `photoPosition` | `35% 50%` · `42% 50%` · `50% 42%` · `50% 50%` · `50% 58%` · `58% 50%` · `65% 50%` | 7가지 |
| `photoScale` | `1` · `1.025` · `1.05` · `1.075` | **`main.js:346` 이 1~1.12 로 자른다.** 그 밖의 값은 조용히 무시된다 |
| `photoMirror` | `true` / `false` | 글자·시계·비대칭 구조가 찍힌 사진은 반전하지 마라 (뒤집힌 글씨가 보인다) |

같은 사진을 여러 번 쓸 때는 **한 묶음 안에서 네 값의 조합이 서로 달라야** 한다. 위치만 바꾸고 배율을 그대로 두면 8개 중 7개까지만 갈라진다.

### 확인

```bash
node scripts/report-photo-duplicates.mjs        # 겹침 목록·요약
node scripts/report-photo-duplicates.mjs --ids  # 고칠 id 만 (한 줄에 하나, 지금 59줄)
node scripts/ensure-lookbook-honesty.mjs        # 겹침이 늘면 빨간불
```

`ensure-lookbook-honesty.mjs` 에 **한도(`DUP_CEILING = 59`)** 를 걸어 뒀다. 더 나빠지면 실패한다. 겹침을 줄이면 검사가 그 사실을 알려주니, **그때 `DUP_CEILING` 을 새 숫자로 내려 잡아라.** 안 내리면 다음 사람이 다시 59까지 늘릴 수 있다.

### 이 방법의 한계 — 솔직히 알고 시작해라

크롭을 바꾼다고 **다른 방이 되는 것은 아니다.** 현관은 사진이 2장인데 시안이 37개다. 크롭을 다 갈라도 손님은 같은 현관을 확대·축소해 가며 30번 본다. **이건 완치가 아니라 응급처치다.** 겹침을 0으로 만드는 것은 "명백히 같은 것"을 없애는 일이고, 진짜 해결은 할 일 B다.

## 2. 할 일 B — AI 이미지 19장 추가 ★사장님이 정하셨다

**2026-07-28, 사장님이 세 가지 안(실제 시공 사진 / AI 이미지 추가 / 시안 수 축소) 중 「AI 이미지 추가」를 고르셨다.** 다시 묻지 말고 진행해라.

### 왜 19장인가

사진이 모자란 순서:

| 공간 | 사진/시안 | 한 장이 감당하는 시안 | 추가할 장수 |
|---|---|---|---:|
| 현관 | 2 / 37 | **18.5개** (한 장이 33번) | **6** |
| 아이방 | 3 / 37 | 12.3개 | **5** |
| 서재 | 4 / 37 | 9.3개 | **4** |
| 드레스룸 | 4 / 37 | 9.3개 | **4** |
| 욕실·침실 | 8 / 38 | 4.8개 | 0 |
| 거실·주방 | 17·11 / 38 | 2.2·3.5개 | 0 |

기준은 **사진 한 장당 최대 5개 시안**이다. 이 선을 넘지 않으면 8공간 모두 사진 8장 이상이 되고 겹침을 0으로 만들 수 있다. 최대 4개까지 낮추려면 31장이 필요한데, **19장을 먼저 끝내고 다시 판단해라** — 현관을 33번에서 5번으로 내리는 것이 12장을 더 만드는 것보다 훨씬 크게 체감된다.

### 사양은 따로 있다

**`integrations/사진-생성-사양.json`** — 19장 전부의 파일명·공간·스타일·덮을 구조·생성 프롬프트가 들어 있다. 사양의 `스타일`·`덮을_구조` 값은 **전부 `data/site.json` 에 실제로 있는 값인지 대조해 두었다**(지어낸 값 0건).

특히 `모든_이미지_공통_금지` 다섯 줄을 그냥 지나치지 마라. 요약하면:

- **글자를 넣지 마라** — `photoMirror` 로 뒤집으면 글자가 거꾸로 보인다. 생성 모델이 만드는 글자는 대개 뜻 없는 기호다.
- **사람을 넣지 마라** — 손님은 '우리집'을 상상하러 온 것이지 남의 집에 사는 사람을 보러 온 것이 아니다.
- **천장 2.3~2.4m 한국 아파트 비율을 지켜라** — 서양식 대저택처럼 나오면 손님이 "우리집이랑 다르네" 하고 나간다.
- **시공 흔적·현장 자재·작업자를 넣지 마라** — 이 카탈로그는 `category: "AI추천"` 이다. 실적 사진으로 오해되면 거짓말이 된다.

### 남은 두 안은 왜 안 골랐는지 (되묻지 않게 적어 둔다)

- **실제 시공 사진** — 지금 카탈로그가 전부 `AI추천` 이라, 실사진을 섞으면 어느 것이 실제 시공인지 화면에 표시해야 한다. 표시 없이 섞으면 거짓말이 된다. 나중에 별도 '시공 사례' 섹션으로 하는 편이 맞다.
- **시안 수 축소** — 골랐다면 `index.html:220` 의 `총 300가지`·`공간별 37~38가지` 와 `README.md` 도 같이 고쳐야 했다. `ensure-lookbook-honesty.mjs` 가 표기와 실제 개수 불일치를 잡으므로 잊어버릴 수는 없다.

## 3. 곁다리로 발견한 것 (급하지 않다)

**① `imageAlt` 에 공간 이름이 두 번 들어간 시안 232건**

```
"라인리스 화이트 현관 현관 인테리어 참고 이미지"
"무몰딩 플랫폼 침실 침실 인테리어 참고 이미지"
```

`"{제목} {공간} 인테리어 …"` 로 조립하면서 제목이 이미 공간 이름으로 끝나는 것을 못 걸렀다. 화면에는 안 보이지만 **스크린리더가 그대로 읽고, 검색엔진이 그대로 색인한다.** 조립할 때 제목 끝이 공간 이름이면 빼면 된다.

**② `imageAlt` 가 아예 없는 초기 39건** — `main.js` 가 `imageAlt || title` 로 받아 주므로 깨지지는 않는다. ①을 고칠 때 같이 채우면 된다.

**③ 한 번도 안 쓰이는 사진 2장 — 2026-07-28 처리 완료**

`japandi-hinoki-bath-24.jpg` 를 `…catalog110-japandi-07`(재팬디 「미장 스파 욕실」)에, `travertine-spa-bath.jpg` 를 `…catalog110-warm-beige-07`(웜 베이지 「크림 스톤 욕실」)에 배정했다. 두 사진을 실제로 열어 보고 시안의 스타일·제목과 맞는지 확인한 뒤 붙였다. 욕실 겹침 8 → 6, 전체 61 → 59.

남는 교훈: **사진을 만들기 전에 저장소에 이미 있는 것부터 다 쓰고 있는지 보라.**

## 4. 건드리지 말 것

- **`js/main.js` 의 `portfolioPhotoStyle()`** — 크롭을 어떻게 그리는지는 지금이 맞다. 데이터만 고쳐라.
- **`aiDesign` · `area` · `budget` · `materials`** — 예상비용이 이 값들로 계산된다. 사진을 고치는 일에 금액이 딸려 움직이면 안 된다. `node scripts/verify-space-cost-estimates.mjs` 가 지킨다.
- **시안 `id`** — 손님이 공유한 링크(`#look=`)와 상담 폼의 '관심 디자인'이 id 로 걸린다. id 를 바꾸면 이미 나간 링크가 다른 시안을 연다.
- **`data/site.json` 의 `portfolio` 개수를 줄이는 것** — 할 일 B의 3번을 사장님이 고른 경우에만.
