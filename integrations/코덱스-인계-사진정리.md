## 0. 먼저 알아야 할 것

### 손님이 시안을 보는 방식

손님은 제목·자재 목록을 읽지 않는다. **사진으로 훑는다.** 그래서 화면 한 칸의 정체는 이 넷이다:

```js
// js/main.js:344  portfolioPhotoStyle()
photo + photoPosition + photoScale + photoMirror
→ object-position:${position};transform:scale(${scale}) scaleX(${mirror});
```

넷이 전부 같으면 제목이 달라도 **같은 시안 두 개**다. 현관 37개를 훑는 손님은 같은 사진을 8번 본다.

## 1. 할 일 A — 61건에 크롭 지정 (지금 할 수 있는 것)

### 방법

`data/site.json` 의 해당 시안에 세 필드를 더한다. 이미 쓰이고 있는 값의 범위를 벗어나지 마라.

```json
{
  "id": "design-20260723-catalog110-minimal-05",
  "photo": "assets/designs/arch-entry-24.jpg?v=20260728-recrop-01",
  "photoPosition": "35% 50%",
  "photoScale": 1.05,
  "photoMirror": false
}
```

| 필드 | 쓰이고 있는 값 | 주의 |
|---|---|---|
| `photoPosition` | `35% 50%` · `42% 50%` · `50% 42%` · `50% 50%` · `50% 58%` · `58% 50%` · `65% 50%` | 7가지 |
| `photoScale` | `1` · `1.025` · `1.05` · `1.075` | **`main.js:346` 이 1~1.12 로 자른다.** 그 밖의 값은 조용히 무시된다 |
| `photoMirror` | `true` / `false` | 글자·시계·비대칭 구조가 찍힌 사진은 반전하지 마라 (뒤집힌 글씨가 보인다) |

같은 사진을 여러 번 쓸 때는 **한 묶음 안에서 네 값의 조합이 서로 달라야** 한다. 위치만 바꾸고 배율을 그대로 두면 8개 중 7개까지만 갈라진다.

### 확인

```bash
node scripts/report-photo-duplicates.mjs        # 겹침 목록·요약
node scripts/report-photo-duplicates.mjs --ids  # 고칠 id 만 (한 줄에 하나, 지금 61줄)
node scripts/ensure-lookbook-honesty.mjs        # 겹침이 늘면 빨간불
```

`ensure-lookbook-honesty.mjs` 에 **한도(`DUP_CEILING = 61`)** 를 걸어 뒀다. 더 나빠지면 실패한다. 겹침을 줄이면 검사가 그 사실을 알려주니, **그때 `DUP_CEILING` 을 새 숫자로 내려 잡아라.** 안 내리면 다음 사람이 다시 61까지 늘릴 수 있다.

### 이 방법의 한계 — 솔직히 알고 시작해라

크롭을 바꾼다고 **다른 방이 되는 것은 아니다.** 현관은 사진이 2장인데 시안이 37개다. 크롭을 다 갈라도 손님은 같은 현관을 확대·축소해 가며 30번 본다. **이건 완치가 아니라 응급처치다.** 겹침 61을 0으로 만드는 것은 "명백히 같은 것"을 없애는 일이고, 진짜 해결은 할 일 B다.

## 2. 할 일 B — 사진 확보 (사장님 판단이 필요하다)

**혼자 정하지 마라.** 사진을 어디서 가져올지는 돈·저작권·정직성이 걸린 문제라 사장님 결정 사항이다. 선택지를 정리해 물어라:

1. **실제 시공 사진** — 가장 좋다. 사장님이 찍어 둔 현장 사진이 있는지. 다만 지금 카탈로그는 `category: "AI추천"` 이라 실사진을 섞으면 **어느 것이 실제 시공인지 표시**해야 한다. 섞어 놓고 말 안 하면 거짓말이 된다.
2. **AI 생성 이미지 추가** — 지금과 같은 성격. 7/27 배치가 `.webp` 8장을 새로 넣은 전례가 있다(`assets/designs/ai-300-*.webp`).
3. **시안 수를 줄인다** — 현관 37개를 12개로 줄이면 사진 2장으로도 겹침 없이 갈 수 있다. **300이라는 숫자보다 안 겹치는 게 중요하다면** 이쪽이 정직하다.

3번을 고르면 `index.html:220` 의 `총 300가지`·`공간별 37~38가지` 문구와 `README.md` 도 같이 고쳐야 한다. `ensure-lookbook-honesty.mjs` 가 표기와 실제 개수가 다르면 실패시키니 잊어버릴 수는 없다.

## 3. 곁다리로 발견한 것 (급하지 않다)

**① `imageAlt` 에 공간 이름이 두 번 들어간 시안 232건**

```
"라인리스 화이트 현관 현관 인테리어 참고 이미지"
"무몰딩 플랫폼 침실 침실 인테리어 참고 이미지"
```

`"{제목} {공간} 인테리어 …"` 로 조립하면서 제목이 이미 공간 이름으로 끝나는 것을 못 걸렀다. 화면에는 안 보이지만 **스크린리더가 그대로 읽고, 검색엔진이 그대로 색인한다.** 조립할 때 제목 끝이 공간 이름이면 빼면 된다.

**② `imageAlt` 가 아예 없는 초기 39건** — `main.js` 가 `imageAlt || title` 로 받아 주므로 깨지지는 않는다. ①을 고칠 때 같이 채우면 된다.

**③ 한 번도 안 쓰이는 사진 2장** — `japandi-hinoki-bath-24.jpg` · `travertine-spa-bath.jpg`. 둘 다 욕실이고 욕실은 사진이 모자란 공간이다(8/38). **할 일 A를 하기 전에 이 2장부터 욕실 겹침 8건에 배정하면**, 크롭을 갈라 흉내 내는 대신 진짜로 다른 방을 8건 중 몇 건에 줄 수 있다. 여기서 시작해라.

## 4. 건드리지 말 것

- **`js/main.js` 의 `portfolioPhotoStyle()`** — 크롭을 어떻게 그리는지는 지금이 맞다. 데이터만 고쳐라.
- **`aiDesign` · `area` · `budget` · `materials`** — 예상비용이 이 값들로 계산된다. 사진을 고치는 일에 금액이 딸려 움직이면 안 된다. `node scripts/verify-space-cost-estimates.mjs` 가 지킨다.
- **시안 `id`** — 손님이 공유한 링크(`#look=`)와 상담 폼의 '관심 디자인'이 id 로 걸린다. id 를 바꾸면 이미 나간 링크가 다른 시안을 연다.
- **`data/site.json` 의 `portfolio` 개수를 줄이는 것** — 할 일 B의 3번을 사장님이 고른 경우에만.
