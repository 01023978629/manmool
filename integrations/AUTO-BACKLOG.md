# 자동 진행 백로그 (주간 루틴이 읽는 파일)

매주 월요일 아침 자동으로 도는 **만물인테리어 주간 운영 점검** 루틴이 이 파일을 읽고,
`[자동가능]` 표시가 붙은 항목 중 **맨 위 미완료 1건**을 골라 진행한다.

> **왜 목록으로 두는가** — "알아서 개발해줘"라고 열어두면 매주 다른 곳을 건드려
> 사장님이 쓰는 기능이 흔들린다. 무엇을 할지 먼저 여기 적어두고, 루틴은 그 안에서만 움직인다.

## 루틴이 지켜야 할 규칙

1. **한 번에 1건만.** 욕심내지 않는다. 남는 시간엔 점검 결과를 자세히 적는다.
2. 시작 전 그 항목이 **아직 유효한지 확인**한다. 이미 고쳐졌으면 `[x]`로 체크만 하고 다음으로.
3. 손대기 전과 후에 **전체 회귀를 돌린다.** 손대기 전이 이미 빨간불이면 그걸 먼저 보고하고 멈춘다.
4. **main 에 직접 푸시 금지.** 작업 브랜치에 올리고 PR을 연다.
   PR 도구가 없는 세션이면 브랜치만 올리고 브랜치명을 보고한다.
5. 아래는 **절대 자동으로 하지 않는다** — 사장님 승인 없이는 손대지 않는다:
   - 저장 데이터 구조(serializeData/applyData) 변경
   - 고객에게 실제로 나가는 발송(문자·알림톡·메일) 켜기
   - 외부 서비스 설정·키 변경, 요금이 발생하는 설정
   - 사장님이 매일 쓰는 화면의 동작·배치 변경
6. 회귀가 깨졌는데 **원인을 못 찾으면 되돌리고 보고**한다. 억지로 밀어붙이지 않는다.
7. 새로 발견한 결함은 직접 고치지 말고 **이 파일 맨 아래 '발견' 절에 추가**만 한다(다음 주 후보).

## 매주 하는 운영 준비 점검 (코드 변경 없음)

돈 벌 준비가 되어 있는지 확인한다. 하나라도 빨간불이면 **그게 최우선 보고 사항**이다.

**저장소만 있으면 되는 것 — 매주 반드시 수행**

- [ ] 상담 접수 경로가 유지되는가 — `data/config.json` 의 `forms.enabled=true` + `endpoint`·`accessKey` 존재
      (이게 꺼지면 **손님 문의가 다시 새기 시작한다**. 이 항목이 빨간불이면 다른 무엇보다 먼저 알려라)
- [ ] 접수 판정 일치 — `node scripts/ensure-lead-route-parity.mjs`
- [ ] 무결성 스크립트 전부 통과 — `for f in scripts/*.mjs; do node "$f"; done`
- [ ] 계약 서버 회귀 통과 — `cd contract-backend && npm test`
- [ ] 지난 한 주 커밋에 마무리 안 된 작업이나 회귀 위험이 없는가 — `git log --since=7.days`

**바깥 서비스 생존 확인 — 막히면 그냥 넘어갈 것**

⚠️ 이 세션의 네트워크 정책이 외부 접속을 막고 있을 수 있다(실측: `manmool-contract.fly.dev`·
`01023978629.github.io` 둘 다 프록시가 403으로 차단). **차단되면 우회하지 말고 "확인 불가"로 한 줄만
적고 넘어가라.** 매주 같은 실패를 길게 쓰지 마라.

- [ ] 홈페이지 — `curl -sS -m 20 -o /dev/null -w '%{http_code}' https://01023978629.github.io/manmool/`
- [ ] 계약 서버 — `curl -sS -m 30 https://manmool-contract.fly.dev/healthz`
      (Fly.io 절전 설정이라 첫 응답이 느릴 수 있다. 타임아웃을 넉넉히 주고, 느린 것과 죽은 것을 구분하라)
      · `live:false` 는 아직 정상(알림톡 설정 대기). 한 줄로만 적고 매주 반복 설명하지 마라.

> **더 나은 방법이 백로그에 있다** — 바깥 서비스 생존 확인은 인터넷이 열려 있는
> 구글 Apps Script 파수꾼이 맡는 게 맞다(백로그 5번). 그게 되기 전까지는 이 절이 임시방편이다.

## 개발 백로그 (위에서부터)

### [자동가능] 1. 카카오 링크를 https 로 바꾸기
`data/config.json` 의 `kakao.chatUrl`·`kakao.channelAddUrl` 이 `http://` 로 되어 있다.
홈페이지는 HTTPS 라 브라우저가 이 링크를 막거나 경고할 수 있다.
→ 두 값의 `http://` 를 `https://` 로. 다른 값은 건드리지 않는다.

### [자동가능] 2. 공개 사이트 링크·메타 무결성 검사 추가
지금 내부 링크 깨짐·페이지 메타 누락을 확인하는 자동 검사가 없다(사람이 수동으로 훑어야 함).
→ `scripts/ensure-site-integrity.mjs` 신설:
   - 모든 `*.html` 의 내부 링크가 실제 파일을 가리키는지(404 방지)
   - 각 페이지에 `<title>`·`description`·`canonical` 이 있는지
   - `sitemap.xml` 에 실제 존재하는 페이지가 빠짐없이 들어 있는지
   - `http://` 외부 링크가 남아 있지 않은지(혼합 콘텐츠)
   실패 시 무엇이 어디서 깨졌는지 파일·줄을 찍을 것. 기존 `ensure-*.mjs` 스타일을 따른다.

### [자동가능] 3. 알림톡 설치 문서를 실제 코드와 대조·정정
`contract-backend/SETUP-ALIMTALK.md` 와 `integrations/alimtalk-templates.md` 가
실제 코드(`src/providers/index.mjs` 의 환경변수, `src/server.mjs` 가 넘기는 치환변수)와
어긋나는 곳이 없는지 대조한다. 사장님이 문서대로 따라 했을 때 실패하는 지점을 찾아 고친다.
문서만 고치고 코드는 건드리지 않는다.

### [자동가능] 4. 상담 접수 실패 시 재시도 큐
지금은 Web3Forms 전송이 실패하면 손님이 **다시 시도 버튼을 직접 눌러야** 한다.
전파가 끊긴 지하 현장 등에서 그대로 이탈하면 문의가 사라진다.
→ 실패한 접수를 `localStorage` 에 담아두고, 다음 방문·온라인 복귀 시 자동 재전송.
   중복 전송 방지(같은 `id` 는 한 번만), 성공하면 큐에서 제거.
   ※ 손님 개인정보가 브라우저에 남으므로 기존 90일 자동 삭제 정책을 그대로 따를 것.

### [PC필요] 5. 파수꾼이 서비스 생존까지 확인하게 하기
주간 루틴이 도는 환경은 외부 접속이 막혀 있어 홈페이지·계약 서버가 살아 있는지 확인하지 못한다.
반면 구글 Apps Script 파수꾼은 **인터넷이 열린 구글 서버에서 매일 아침 돈다.**
→ `apps-script/Watchdog.gs` 에 하루 1회 생존 확인을 추가:
   - `UrlFetchApp.fetch` 로 홈페이지 200 여부, 계약 서버 `/healthz` 의 `ok`
   - 죽어 있으면 그날 캘린더 알림 맨 위에 `⚠️ 홈페이지 응답 없음` 처럼 얹는다
   - **실패해도 파수꾼 본체가 죽지 않게** 각각 try/catch, `muteHttpExceptions:true`, 짧은 타임아웃
   - Fly.io 는 절전이라 첫 응답이 느리다 — 느린 것과 죽은 것을 구분할 것
가치: 홈페이지가 죽으면 그날부터 문의가 0이 되는데 지금은 알 방법이 없다.

⚠️ **자동으로 하지 말 것.** Watchdog.gs 를 고치면 사장님이 Apps Script 에 다시 붙여넣어야 하고,
그 작업은 폰에서 꽤 번거롭다. 사장님이 PC 를 쓰는 세션에서 함께 처리한다.

### [대기중] 6. 카카오 채널 켜기 — 사장님이 개설 진행 중
`kakao.ready=false` 라 카톡 관련 버튼이 어디에도 안 뜬다.

**2026-07-25 확인됨: 사장님이 채널을 개설하기로 했고 곧 완료 예정.**
→ 루틴은 이 항목을 **다시 여쭙지 말 것.** 자동으로 켜지도 말 것.
   `channelPublicId` 확정값을 받은 뒤 사장님과 함께하는 세션에서 처리한다.

처리할 때 할 일(한 번에):
- `kakao.ready` 를 사용으로 전환
- `chatUrl`·`channelAddUrl` 의 `http://` → `https://` (백로그 1번과 함께 처리하면 한 번에 끝난다)
- 손님 화면(상담 완료 후)에서 카톡 버튼이 실제로 뜨는지 확인
  — `js/inquiry.js` 의 `kakaoReady = !!(kakao.ready && kakaoUrl)` 조건을 통과해야 보인다

이게 되면 알림톡(SOLAPI)도 신청 가능해진다 — 채널이 발신프로필이라 채널 없이는 템플릿 심사 자체가 안 된다.

### [확인필요] 7. hyeonjang(운영앱) 쪽 작업
운영앱은 별도 저장소라 주간 루틴 세션에는 딸려오지 않는다.
운영앱 관련 항목이 생기면 여기 적어두고, **사장님과 함께하는 세션에서** 처리한다.
