### 3-1. ✅(완료) 본인확인 문자가 발송되지 않는다 (전자계약 전체가 0건)

### 3-2. ✅(완료) 재발송하면 정확한 번호가 거부된다

**어디** `contract-backend/src/service.mjs:244`
```sql
SELECT * FROM otp_challenges WHERE party_id=? AND verified_at IS NULL ORDER BY id DESC LIMIT 1
```
이 `id` 는 `src/crypto.mjs` 가 만드는 **난수**라 시간순이 아니다. 재발급하면 옛 챌린지가 만료 상태로
남아 있어 서버가 옛것을 집으면 `OTP_EXPIRED` 가 난다.

**고칠 것**

- 발급 상한을 '평생 5회' → **'최근 30분 5회'**(`AND created_at >= ?`)로. 무차별 대입 방어는 유지.

### 3-5. ✅(완료) 세무 경로만 '집계 제외'와 중복제거를 무시한다

**어디** `/workspace/hyeonjang/index.html`
대시보드(`projStats`)는 `dedupeEstimates` + `exSum` 제외를 지키는데, 아래는 원시 필터로 훑는다.

**앱이 제외했다고 말해놓고 세무 경로만 무시하는 셈이다.**

**고칠 것** 매출 집계 진입점을 한 곳으로 모아라. 새 엔진·새 탭을 만들지 말고 기존 함수를 재사용.
`_fromQuote` 가상 파일 제외 등 기존 예외를 깨뜨리지 마라.

**검증** 위 예시와 중복 견적(엑셀+PDF) 두 경우 모두, 대시보드·월말 결산·부가세 매출세액·세무 분기 정산
