# 문의 접수함 (Lead Inbox) Apps Script 백엔드

공개 사이트 폼(인테리어·누수·관리사무소 파일럿)이 보내는 상담 문의를 **구글 시트에 이력으로 남기고**, 대표가 `lead-inbox.html` 에서 승인·보류·거절을 기록하는 서버입니다. 메일(Web3Forms)은 지금처럼 그대로 나가고, 이 접수함은 "무엇이 들어왔고 어떻게 판정했나"의 정본입니다.

이 폴더는 기존 사진 중계(`hyeonjang/apps-script/`)·관리사무소 포털(`hyeonjang/apps-script-office-portal/`)과 **별도 Apps Script 프로젝트**로 배포합니다. 그쪽 스크립트 속성·시트·배포 URL과 섞지 마세요.

## 무엇이 남나

| 탭 | 한 줄의 뜻 |
|---|---|
| `문의` | 문의 한 건. 접수번호(LD-날짜-순번)·받은 시각·상태(신규/승인/보류/거절)·판정 시각·손님이 적은 항목 전부·메일 발송 여부·사람이 읽는 본문(`message`) |
| `이력` | 문의에 일어난 일 한 줄. 접수·판정마다 이전 상태→새 상태·메모·행위자·시각 |
| (보관) | 처리방침대로 **거절은 판정 90일, 승인은 1년** 뒤 문의·이력을 서버가 지운다(로그인 때 + 매일 트리거). 신규·보류는 판정 전이라 남는다 |
| `세션` | 관리 화면 로그인 세션(토큰 해시만). 30일 지난 것은 자동 정리 |

## 보안 모델

- 접수(`leadCreate`)는 로그인 없이 받되 10분에 60건 상한(전역), 문의 ID(UUID) 중복이면 새 줄을 만들지 않고 기존 접수번호를 돌려줍니다 — 폼 재시도가 두 줄을 만들지 않습니다.
- 손님 입력이 시트 수식이 되는 첫 글자(`=` `+` `-` `@` 탭 줄바꿈)로 시작하면 앞에 작은따옴표를 붙여 글자로 고정합니다. 거부하지 않습니다(`-급해요` 같은 메모를 잃지 않기 위해).
- 관리 로그인은 대표만 아는 **관리 비밀번호**(스크립트 속성) 하나입니다. 비교는 HMAC 뒤 상수시간 비교, 5회 연속 실패 시 15분 잠금.
- 세션 토큰은 로그인 응답에서 한 번만 원문으로 돌려주고 서버에는 HMAC 해시만 남깁니다. 8시간 뒤 만료.
- 판정(`leadDecide`)은 클라이언트 UUID `requestId`로 멱등 — 같은 버튼을 두 번 눌러도 이력이 한 줄입니다.
- 상태 전이는 `신규→승인/보류/거절`, `보류→승인/거절`, `거절→보류`만. **승인은 되돌리지 않습니다**(현장으로 넘어간 뒤 기록이 사라지면 안 됩니다). 거절에는 사유 메모가 필수입니다.
- 응답에 비밀번호·토큰 해시·시트 ID를 싣지 않습니다.

로그인 없이 호출 가능한 action은 `leadHealth`, `leadCreate`, `leadLogin`뿐입니다.

## 최초 설치 (대표님, 약 30분)

1. 접수함 전용 Google Spreadsheet를 **새로** 만듭니다. 주소의 `/d/` 와 `/edit` 사이 긴 문자열이 시트 ID입니다.
2. script.google.com 에서 **새 프로젝트**를 만들고 이 폴더의 `Code.gs`, `LeadInboxPure.gs`, `appsscript.json`을 같은 이름으로 넣습니다. (`appsscript.json`은 프로젝트 설정 → "appsscript.json 매니페스트 파일 표시"를 켜야 보입니다.)
3. 프로젝트 설정 → **스크립트 속성**에 아래 다섯 개를 등록합니다.
   - `LEAD_INBOX_ENABLED` : `1`
   - `LEAD_INBOX_SHEET_ID` : 1단계 시트 ID
   - `LEAD_INBOX_SESSION_SECRET` : 32자 이상 무작위 문자열 (예: 비밀번호 생성기로 40자)
   - `LEAD_INBOX_LOGIN_PEPPER` : 위와 **다른** 32자 이상 무작위 문자열
   - `LEAD_INBOX_ADMIN_CODE` : 관리 화면에 들어갈 **관리 비밀번호** (8자 이상, 공백 없음). 대표님만 아는 값. 앱·문서·카톡 어디에도 적지 마세요.
   - (선택) `LEAD_INBOX_NOTIFY_TO` : 새 문의가 올 때 알림 메일을 받을 주소. 비워 두면 알림 없음. Web3Forms 메일이 실패한 문의도 이 메일은 옵니다(배포 계정의 Gmail 일일 발송 한도 안에서).
4. 편집기에서 함수 `leadInboxSetupSheets_` 를 골라 **실행** 합니다. 권한 승인 창이 뜨면 허용합니다. 시트에 `문의`·`이력`·`세션` 탭과 고정 머리글이 생깁니다.
   이어서 함수 `leadInboxInstallTrigger_` 도 한 번 **실행** 합니다 — 매일 새벽 4시에 보관 기한(거절 90일·승인 1년)이 지난 문의를 지우는 시간 트리거가 걸립니다. 안 걸어도 대표가 접수함에 로그인할 때마다 같은 정리가 돌지만, 로그인이 뜸하면 처리방침 기한을 넘길 수 있어 트리거를 권합니다.
5. **배포 → 새 배포 → 유형: 웹 앱**, 실행 사용자 "나", 액세스 권한 "**모든 사용자**". 배포 후 나오는 `https://script.google.com/macros/s/…/exec` 주소를 복사합니다.
6. 그 주소를 저에게 주시거나 `data/config.json` 의 `inbox.url` 에 넣고 `inbox.enabled` 를 `true` 로 바꿉니다. 배포검사가 주소 형식을 확인합니다.
7. 사이트에서 시험 문의를 한 건 넣고 `lead-inbox.html` 에 관리 비밀번호로 들어가 보이는지 확인합니다. 시험 문의는 화면에서 **거절**(사유: 시험)로 정리하면 됩니다.

코드를 고친 뒤에는 **배포 → 배포 관리 → 편집 → 새 버전**으로 다시 배포해야 반영됩니다. 스크립트 속성은 그대로 유지됩니다.

## 새 문의 알림 메일 (선택)

`LEAD_INBOX_NOTIFY_TO` 에 주소를 넣으면 접수(`leadCreate`)마다 그 주소로 평문 메일이 갑니다 — 제목에 서비스·이름·지역·접수번호, 본문에 메일과 같은 형식의 문의 내용과 접수함 링크. 폼 재시도로 같은 문의가 다시 오면(중복) 보내지 않고, 알림이 실패해도 접수는 이미 시트에 있으므로 손님에게 오류를 돌려주지 않습니다. 발송은 배포 계정(MailApp) 한도를 쓰며 한도가 차면 건너뜁니다.

## 끄기

`LEAD_INBOX_ENABLED` 를 `0` 으로 바꾸면 접수·로그인 모두 `not-configured` 로 거절합니다. 사이트 폼은 메일 경로만으로 계속 동작합니다.
