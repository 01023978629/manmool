# 옛 계약 자료 옮기기 — 사장님 PC 에서 하시는 절차

종료한 Fly 서버에서 받아 두신 백업 DB 를 새 시트로 옮깁니다.

**원본 파일은 한 글자도 바뀌지 않습니다.** 이 절차의 어느 단계에도 원본에 쓰는 동작이 없습니다.

## 1. 먼저 시늉만 돌립니다 (dry-run)

명령 프롬프트(`cmd`)나 PowerShell 을 열고, 이 저장소를 받아 둔 폴더에서:

```
node apps-script-contract/tools/migrate-sqlite-to-sheets.mjs --db="D:\만물인테리어_백업\contract_20260730_before_fly_delete.db"
```

**`--write` 를 붙이지 않았으므로 파일이 하나도 만들어지지 않습니다.**
화면에 보고서가 그대로 찍힙니다.

### 맨 처음 나오는 세 줄이 가장 중요합니다

```
원본 : D:\만물인테리어_백업\contract_20260730_before_fly_delete.db (…바이트)
지문 : 4fabba67249b9480da019ae998713d24a7082a67ba316aa12ccf958fb6541840
기대 : 4fabba67249b9480da019ae998713d24a7082a67ba316aa12ccf958fb6541840
```

**`지문` 과 `기대` 가 같아야 합니다.**
다르면 이런 상자가 뜨고 그 자리에서 멈춥니다:

```
╔══════════════════════════════════════════════════════════════╗
║  ⚠ 원본 지문이 기대값과 다릅니다.                              ║
║  다른 백업 파일일 수 있습니다. 그대로 옮기면 엉뚱한 자료가      ║
║  시트에 올라가고, 시트에는 되돌리기가 없습니다.                 ║
╚══════════════════════════════════════════════════════════════╝
```

**이때 `--allow-hash-mismatch` 를 붙여 억지로 넘기지 마세요.**
먼저 이것부터 확인하세요:

1. 파일 경로를 잘못 넣지 않았는가 (다른 날짜의 백업을 가리키고 있지 않은가)
2. `.db-wal` · `.db-shm` 파일이 같은 폴더에 함께 있는가
   → **이 두 파일도 반드시 함께 두셔야 합니다.** 마지막 기록이 여기 남아 있을 수 있고,
     지문은 본 파일(`.db`)만 보고 계산합니다
3. 파일을 압축했다 풀거나, 메일에 첨부했다 받지 않았는가

셋 다 확인했는데도 다르면 **멈추고 알려 주세요.**

### 끝났을 때 나오는 값

| 화면 마지막 줄 | 뜻 | 하실 일 |
| --- | --- | --- |
| `통과` | 대조가 전부 맞았습니다 | 2장으로 |
| `실패` | 어긋난 항목이 있습니다 | **5장으로.** 진행하지 마세요 |

명령이 끝난 뒤 값(exit code)으로도 알 수 있습니다: `0` = 통과 · `1` = 대조 불일치 · `2` = 시작도 못 함.

## 2. 보고서 읽는 법

보고서는 11개 장으로 되어 있습니다. **1장만 봐도 됩니다.** 나머지는 1장에서 ✗ 가 나왔을 때 봅니다.

### 1장 「대조표」 — 여기가 판정입니다

```
| 검사 | 결과 | 내용 |
| 계약 건수 | ✓ | 원본 5건 → 옮김 5건 (못 옮김 0건) |
| 계약금액 합계 | ✓ | 56,550,000원 → 56,550,000원 |
| 문서 지문(doc_hash) 보존 | ✓ | 지문 있는 계약 4건 중 4건 그대로 |
| 원본 이상 없음 | ✓ | 0건 |
```

**✗ 가 하나라도 있으면 실패입니다.** 어느 항목이 ✗ 인지에 따라 볼 곳이 다릅니다:

| ✗ 가 난 항목 | 볼 곳 | 뜻 |
| --- | --- | --- |
| 옮기지 못한 계약 없음 | **6장** | 넣을 수 없는 줄이 있습니다 |
| 계약금액 합계 / 대금 합계 / 상태별 건수 | **6장** 먼저 | 대개 6장의 "못 옮긴 줄" 때문에 합계가 줄어든 것입니다 |
| 문서 지문 보존 | **6장·7장** | 지문이 있는 계약을 못 옮겼거나, 원본에서 이미 어긋나 있습니다 |
| 원본 이상 없음 | **7장** | **옛 DB 안에서 이미 어긋나 있던** 값입니다 |
| 원본 지문 일치 | 1장 위쪽 | 다른 파일입니다. 1장으로 돌아가세요 |

### 나머지 장이 말하는 것

| 장 | 무엇 | 언제 보나 |
| --- | --- | --- |
| 2 「건수 — 이전 전 / 후」 | 표별 건수 전/후 | 숫자를 손으로 대조하실 때 |
| 3 「금액」 | 계약금액 합계 · 대금 회차 합계 | 돈이 맞는지 |
| 4 「문서 지문」 | `doc_hash` 가 글자 그대로 갔는지 | 위변조 대조의 근거 |
| 5 「서명 링크」 | 살아있음 / 사용됨 / 기한지남 / 취소됨 | 만료된 링크를 어떻게 했는지 |
| **6 「옮기지 못한 줄」** | 넣을 수 없어서 남긴 줄 | **✗ 가 났을 때 제일 먼저** |
| **7 「원본 이상」** | 옛 DB 가 이미 어긋나 있던 줄 | **✗ 가 났을 때** |
| 8 「옮기지 않은 표·칸」 | 새 시트에 자리가 없는 것 | 항상 한 번은 읽어 두세요 |
| 9 「비어 있던 칸을 어디서」 | 없던 값을 어디서 끌어왔는지 | 값의 출처가 궁금할 때 |
| 10 「사건 이름 대응」 | 옛 이름 → 새 이름 | 원장을 대조하실 때 |
| 11 「다음에 할 일」 | 시트에 올리는 순서 | 3장과 같은 내용입니다 |

### 8장은 통과했어도 꼭 읽으세요

새 시트에 **자리가 없어서 안 옮긴 것**들입니다. 예:

- `signatures.image_data` (서명 그림) — 시트 칸에 넣을 수 없는 크기. **지문만** 옮깁니다
- `otp_challenges` (본인확인) — Apps Script 판에는 OTP 가 없습니다
- `app_settings` (운영 설정) — 비밀값이 섞여 있을 수 있어 옮기지 않습니다
- `ip_hash` (접속지 해시) — Apps Script 는 IP 를 주지 않습니다

> **옛 백업 파일을 절대 지우지 마세요.** 8장에 적힌 것은 그 파일에만 남습니다.
> 이관이 끝나도 그 파일은 계속 보관하셔야 합니다.

### 마지막 경고 한 줄 — `PEPPER`

보고서 맨 끝에 이렇게 적혀 있습니다:

> 전화번호 해시(`customerPhoneHash`)는 옛 서버의 `CONTRACT_PEPPER` 로 만든 값입니다.
> Apps Script 의 `PEPPER` 를 **같은 값으로** 두셔야 앞으로 만드는 해시와 대조가 됩니다.

**옛 Fly 서버의 `CONTRACT_PEPPER` 값을 아직 가지고 계시면, 그 값을 Apps Script 의 `PEPPER` 로 쓰세요.**
다른 값을 쓰시면 옛 계약의 전화번호 해시는 영영 대조할 수 없습니다
(마스킹본 `010-****-5678` 은 그대로 보입니다 — 계약 자체는 멀쩡합니다).

값을 잃어버리셨다면 그냥 새 값으로 두시고, **이 사실을 기억해 두세요.**
옛 계약과 새 계약의 번호 해시는 서로 대조되지 않습니다.

## 3. 통과했으면 진짜로 만듭니다

```
node apps-script-contract/tools/migrate-sqlite-to-sheets.mjs --db="D:\만물인테리어_백업\contract_20260730_before_fly_delete.db" --write
```

`apps-script-contract/tools/out/` 에 5개가 생깁니다:

```
Contracts.csv        ContractEvents.csv        Payments.csv        SignTokens.csv
report.md            ← 방금 화면에서 보신 보고서와 같은 내용
```

`report.md` 를 파일로 열어 한 번 더 읽어 보세요. 나중에 대조할 때 이 파일이 근거가 됩니다.

### 3-1. CSV 를 Drive 에 올립니다

1. drive.google.com 에서 아무 폴더나 하나 만듭니다(예: `계약이관_임시`).
2. `out/` 의 **CSV 4개**를 그 폴더에 올립니다. (`report.md` 는 올리지 않아도 됩니다)
3. **공유하지 마세요.** 고객 이름·마스킹 번호·금액이 들어 있습니다.
4. 폴더에 들어가 주소창에서 폴더 ID 를 복사합니다:

```
https://drive.google.com/drive/folders/1AbCdEf...
                                       └── 이 부분 ──┘
```

### 3-2. 시트에 넣습니다

Apps Script 편집기(`만물 전자계약` 프로젝트)에서:

1. 먼저 함수 고르는 칸에서 **`setupSheets`** 를 실행합니다(이미 하셨으면 건너뛰어도 됩니다).
2. 편집기 아무 `.gs` 파일 맨 아래에 이 함수를 임시로 붙여넣습니다:

```javascript
function 이관실행() {
  importFromDriveFolder_('여기에_폴더_ID_붙여넣기');
}
```

3. **`이관실행`** 을 고르고 **`▶ 실행`**.
4. 아래 **`실행 로그`** 를 봅니다:

```
[이전] Contracts ← Contracts.csv
[이전] 넣기 전 0줄 → 넣은 뒤 5줄 (새로 넣음 5줄)
[이전] 건너뜀: 이미 있음 0 · CSV 안 중복 0
...
[이전] 남은 줄 없음. 이전이 끝났습니다.
```

5. **`넣은 뒤` 건수가 `report.md` 2장의 「이전 후」 숫자와 같은지** 눈으로 대조하세요.

### 여러 번 실행해도 안전합니다

- 같은 줄은 **건너뜁니다.** 두 번 들어가지 않습니다.
- 실행 6분 제한에 걸려 `아직 N줄이 남았습니다` 가 나오면 **같은 명령을 다시 실행**하면 됩니다.
  남은 줄부터 이어서 넣습니다.
- **이미 있는 줄을 덮어쓰지 않습니다.** 시트에는 되돌리기가 없기 때문입니다.
- `Settings` 시트에는 넣지 않습니다. 비밀값이 섞여 들어올 자리를 아예 만들지 않았습니다.

### 3-3. 끝난 뒤 치우기

1. 임시로 붙여넣은 `이관실행` 함수를 지웁니다.
2. Drive 의 `계약이관_임시` 폴더를 지웁니다.
3. **PC 의 `apps-script-contract/tools/out/` 폴더를 지웁니다.**
   고객 이름과 금액이 든 파일입니다. (git 에는 올라가지 않습니다 — `.gitignore` 에 있습니다)
4. 백업 DB 원본은 **그대로 두세요.**

## 4. 옮긴 뒤 확인할 것

| 확인 | 어떻게 | 맞아야 하는 값 |
| --- | --- | --- |
| 계약 건수 | `Contracts` 시트의 줄 수 | `report.md` 2장 「이전 후」 |
| 계약금액 합계 | `Contracts` 시트 `amount` 열을 `=SUM()` | `report.md` 3장 |

**숫자가 하나라도 다르면 5장으로 가세요.**

## 5. ★ 불일치가 나왔을 때 — 임의로 고치지 마세요

### 이 도구는 값을 고치지 않습니다

일부러 그렇게 만들었습니다. 어긋난 값을 프로그램이 "그럴듯하게" 맞춰 놓으면,
**원본과 다른 자료가 시트에 올라가고 아무도 그 사실을 모릅니다.**
계약 자료에서 그건 가장 나쁜 일입니다. 그래서 어긋난 것은 그대로 옮기고 보고서에만 적습니다.

### 사장님도 마찬가지입니다 — 먼저 알려 주세요

숫자가 어긋났을 때 시트에서 금액을 손으로 고쳐 맞추고 싶어지실 겁니다.
**하지 마세요.** 어느 쪽이 맞는지 아직 모르기 때문입니다.

| 나쁜 대응 | 왜 나쁜가 |
| --- | --- |
| 시트에서 금액을 고쳐 합계를 맞춤 | 옛 DB 가 맞았을 수도 있습니다. 고치면 근거가 사라집니다 |
| 못 옮긴 줄을 손으로 타이핑해 넣음 | 오타 하나가 문서 지문을 깨뜨립니다 |
| `--allow-source-anomalies` 를 붙여 통과시킴 | 어긋난 사실이 판정에서 사라집니다 |
| 이관을 다시 처음부터 함 | 이미 들어간 줄과 섞입니다 |

### 하실 일 — 이 세 가지만

1. **멈추세요.** `--write` 를 실행하지 않았다면 시트는 아직 안전합니다.
2. **`report.md` 파일을 그대로 보내 주세요.** 요약하지 마시고 파일째로.
   6장·7장이 무엇을 잡았는지가 판단의 근거입니다.
3. **어느 계약인지 아시면 알려 주세요.** 예: "MM-2026-0007 은 작년에 금액을 한 번 조정했다"
   → 이 한 마디가 "원본이 맞는지"를 가릅니다.

### 보고서가 잡는 어긋남과, 각각이 뜻하는 것

| 보고서에 나오는 말 | 뜻 | 누가 답할 수 있나 |
| --- | --- | --- |
| `본문으로 다시 계산한 지문이 저장된 지문과 다릅니다(잠금 후 변조 의심)` | 잠근 뒤에 본문이 바뀌었습니다 | **확인이 필요합니다.** 옛 서버의 버그일 수도, 실제 변조일 수도 있습니다 |
| `고객이 서명할 때 본 지문과 계약에 저장된 지문이 다릅니다` | 고객이 본 것과 저장된 것이 다릅니다 | **가장 무거운 항목입니다.** 그 계약은 따로 보셔야 합니다 |
| `회차 합계(…)와 계약금액(…)이 다릅니다` | 대금 3회차의 합이 총액과 안 맞습니다 | 사장님이 아십니다 — 증액·감액이 있었는지 |
| `이 계약에 대금 회차가 하나도 없습니다` | 대금 표가 비었습니다 | 대개 DRAFT 로 남은 계약입니다. 확인만 하면 됩니다 |
| `모르는 계약 상태입니다: XXX` | 새 체계에 없는 상태 | 옛 서버에만 있던 상태입니다. 그대로 두고 나중에 정리 |
| `계약 본문이 N자로 시트 한 칸 한계를 넘습니다` | 45,000자를 넘습니다 | **잘라 넣으면 지문이 깨집니다.** 그 계약만 따로 처리해야 합니다 |

### 억지로 통과시키는 옵션들 — 언제 쓰나

| 옵션 | 무엇을 하는가 | 언제 |
| --- | --- | --- |
| `--allow-hash-mismatch` | 원본 지문이 달라도 진행 | **다른 백업인 줄 알고도** 옮길 때만 |
| `--allow-source-anomalies` | 원본이 어긋나도 통과로 판정 | 어긋남을 이미 확인하고 "알고 넘어간다"고 정했을 때만 |
| `--drop-dead-tokens` | 죽은 링크(만료·사용됨·취소됨)는 안 옮김 | 옛 링크 기록이 필요 없다고 정하셨을 때 |

**셋 다 혼자 판단해서 쓰지 마세요.** 붙이면 보고서 첫 줄에 붙였다는 사실이 남습니다 —
나중에 "왜 이 자료가 이런가"를 되짚을 수 있게 하려고 그렇게 만들었습니다.

## 6. 이관 도구를 믿어도 되는지 — 직접 확인해 보실 수 있습니다

가짜 DB 를 만들어 도구를 시험해 볼 수 있습니다. 사장님의 자료는 전혀 건드리지 않습니다.

```
# 깨끗한 가짜 DB — 통과가 나와야 합니다
node apps-script-contract/tools/make-fixture-db.mjs --out=apps-script-contract/tools/fixture/clean.db
node apps-script-contract/tools/migrate-sqlite-to-sheets.mjs --db=apps-script-contract/tools/fixture/clean.db --allow-hash-mismatch

# 일부러 어긋뜨린 가짜 DB — 실패가 나와야 합니다
node apps-script-contract/tools/make-fixture-db.mjs --out=apps-script-contract/tools/fixture/dirty.db --dirty
node apps-script-contract/tools/migrate-sqlite-to-sheets.mjs --db=apps-script-contract/tools/fixture/dirty.db --allow-hash-mismatch
```

두 번째가 **실패**로 나와야 도구를 믿을 수 있습니다.
"통과만 잘 나오는 도구"는 아무것도 검사하지 않는 도구와 구분되지 않습니다.

> 이 가짜 DB 들에 든 이름·번호는 전부 지어낸 것입니다. `tools/fixture/` 는 git 에 올라가지 않습니다.

## 7. 자주 막히는 곳

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `node: command not found` | Node 미설치 | https://nodejs.org 에서 LTS 설치 후 창을 새로 여세요 |
| `DatabaseSync is not a constructor` | Node 버전이 낮음 | 22 이상이어야 합니다 (`node --version`) |
| `파일을 찾을 수 없습니다` | 경로에 공백·한글 | 경로 전체를 `"` 큰따옴표로 감싸세요 |
| 지문이 계속 다름 | `.db-wal`·`.db-shm` 을 안 가져옴 | 세 파일을 **같은 폴더**에 함께 두세요 |
| `여기로는 들여올 수 없는 시트입니다` | 시트 이름 오타 | `Contracts` `ContractEvents` `Payments` `SignTokens` 넷만 됩니다 |
| `시트가 없습니다` | 시트를 안 만듦 | `setupSheets` 를 먼저 실행하세요 |
| 실행 로그에 `아직 N줄이 남았습니다` | 6분 제한 | 같은 명령을 **다시 실행**하세요. 이어서 넣습니다 |
| 금액이 시트에서 글자로 보임 | 열 서식 문제 | 열을 선택 → `서식` → `숫자` → `숫자`. 값 자체는 맞습니다 |
