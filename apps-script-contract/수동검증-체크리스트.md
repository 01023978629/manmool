# 수동 검증 체크리스트 — 사람이 눈으로 봐야 하는 것

`node apps-script-contract/test/run.mjs` 가 **닿지 못하는 것만** 모았습니다.

자동 검사가 이미 보는 것(금액 계산·상태 전이·검증 규칙·수식 삽입 방지 로직·열 정의)은
여기 없습니다. **여기 있는 것은 전부 사람이 화면을 보고 판단해야 하는 것들입니다.**

> 한 번에 다 하지 마세요. **A → B → C → D** 순서로, 앞이 통과해야 다음으로 갑니다.
> ⛔ 표시는 **실패하면 그 자리에서 멈추고 계약을 걸지 말아야 하는** 항목입니다.

## A. 설치 직후 (1회)

### A-1 ⛔ 사진 중계가 여전히 멀쩡한가

**가장 먼저 확인하세요.** 이걸 망가뜨리면 며칠 뒤에야 아시게 됩니다.

| | |
| --- | --- |
| 어떻게 | 현장 앱에서 현장 하나에 **사진을 한 장 올려** 봅니다 |
| 통과 | 평소처럼 저장되고, Drive 만물인테리어 폴더에 그 사진이 보임 |
| 실패하면 | **전자계약 파일을 사진 중계 프로젝트에 넣으신 것입니다.** 즉시 중단하고 알려 주세요 |

> 자동 검사는 프로젝트가 몇 개인지 모릅니다. 사람만 알 수 있습니다.

### A-2 ⛔ 권한 승인이 끝났는가

| | |
| --- | --- |
| 어떻게 | 편집기에서 `runSelfTest` 실행 |
| 통과 | 승인 창이 **더는 뜨지 않고** 로그에 `allOk = true` |
| 실패하면 | SETUP.md 5장(“안전하지 않음” 넘어가기)을 다시 하세요 |

승인 창이 뜬다면 아직 안 끝난 것입니다. `고급` → `…(안전하지 않음)으로 이동` → `허용`.

### A-3 시트 5장의 머리행이 Schema.gs 와 같은가

| | |
| --- | --- |
| 어떻게 | 스프레드시트를 열어 탭 5개(`Contracts` `ContractEvents` `Payments` `SignTokens` `Settings`)의 **1행**을 봅니다 |
| 통과 | 열 이름과 **순서**가 [README.md 3-1](./README.md) 표와 같음. `Contracts` 는 `id`부터 `updatedAt`까지 27칸 |
| 실패하면 | `setupSheets` 로그의 `어긋남=` 줄을 그대로 알려 주세요. **손으로 열을 옮기지 마세요** |

> 자동 검사는 `Schema.gs` 안의 정의만 봅니다. **실제 시트에 그대로 적혔는지는 못 봅니다.**

### A-4 Drive 폴더가 제자리에 생기는가

| | |
| --- | --- |
| 어떻게 | `runSelfTest` 로그의 `Drive 폴더 열림 — 폴더 「…」` 이름을 확인 |
| 통과 | 사장님이 3-2 에서 만드신 폴더 이름과 같음 |
| 실패하면 | `DRIVE_FOLDER_ID` 를 다른 폴더 것으로 넣으신 것입니다 |

### A-5 ⛔ 문자 발송이 꺼져 있는가

| | |
| --- | --- |
| 어떻게 | `runSelfTest` 로그에서 `[통과] 문자 발송 꺼짐 — 꺼져 있음(MOCK_OFF)` |
| 통과 | 위 줄이 **통과**로 나옴 |
| 실패하면 | `ALIMTALK_LIVE` 를 지우세요. 켜진 채로 시험하면 **고객에게 진짜로 문자가 갑니다** |

### A-6 배포 주소가 열리고, 아무것도 알려 주지 않는가

| | |
| --- | --- |
| 어떻게 | `/exec` 주소를 브라우저에 그냥 붙여넣습니다 |
| 통과 | “만물인테리어 전자계약 / 문자로 받으신 링크를 눌러 주세요” 안내와 전화번호만 보임 |
| 실패하면 | 계약 목록·동작 목록·설정 상태가 보이면 알려 주세요 |

`/exec?action=health` 도 열어 보세요. `configured` 에 `true`/`false` 만 있고 **값은 하나도 없어야** 합니다.

---

### A-7 ⛔ 서명 처리 모듈이 설치되어 있는가

| | |
| --- | --- |
| 어떻게 | `/exec?action=health` 를 열어 `modules` 안의 `sign` 값을 봅니다 |
| 통과 | `"sign": true` |
| `false` 라면 | **`Sign.gs` 를 안 붙여넣으셨습니다.** A~B 는 계속하셔도 되지만, **C 장(폰 서명)은 못 합니다.** 고객에게 링크를 보내지 마세요 |

> 같은 자리에 `notify` 와 `ai` 도 보입니다.
> `ai` 가 `true` 이고 `ai.gemini` 가 `true` 면 **기기에 Gemini 키를 안 넣어도 AI 가 돕니다**(무료).
> `notify` 는 `true` 여도 실제 발송은 별도로 꺼져 있습니다 — 그게 맞습니다.

## B. 시험 계약 한 건 — 사장님 본인 번호로

**반드시 사장님 본인 번호로만** 하세요. 고객 번호를 쓰지 마세요.

### B-1 현장 앱 잠금이 실제로 잠기는가

| | |
| --- | --- |
| 어떻게 | ① 자가진단 **전에** 계약 버튼을 눌러 봅니다 ② 주소를 **일부러 틀리게** 넣고 `🩺 자가진단` |
| 통과 | ① 눌리지 않음 ② `자가진단 실패 — 계약 버튼…` 이 뜨고 여전히 잠김 |
| 실패하면 | 틀린 주소로도 계약이 나갑니다. 즉시 알려 주세요 |

그다음 **바른 주소·토큰**으로 자가진단 → `✅ 자가진단 통과` 를 확인하고 다음으로.

### B-2 계약을 만들고 시트에 값이 들어갔는가

현장 앱에서 시험 계약을 한 건 만듭니다(금액은 `1,234,567원` 처럼 **끝자리가 홀수인 값**으로).

| 볼 곳 | 통과 기준 |
| --- | --- |
| `Contracts` 새 줄 | `id` 가 `ct_…` · `contractNo` 가 `MM-2026-XXXX` · `status` 가 `DRAFT` |
| `amount` 칸 | **오른쪽 정렬**(숫자로 들어감). 왼쪽 정렬이면 글자로 들어간 것 |
| `customerPhoneMasked` | `010-****-XXXX` 형태 |
| ⛔ **전화번호 원문** | 시트 어느 칸에도 **가운데 4자리가 보이면 안 됩니다** |
| `Payments` 3줄 | `계약금`+`중도금`+`잔금` 합이 **계약금액과 정확히 같음** (1원도 안 남아야 함) |
| `ContractEvents` | `CONTRACT_CREATED` 한 줄. `detail` 에 전화번호·토큰이 없어야 함 |

> 자동 검사는 “합이 같아야 한다”는 규칙을 검사합니다.
> **시트에 그 값이 실제로 그대로 적혔는지는** 여기서만 알 수 있습니다.

### B-3 ⛔ 수식 삽입이 실제 시트에서 막히는가

**자동 검사가 확실히 답하지 못하는 부분입니다.** 구글시트가 값을 어떻게 해석하는지는
실제 시트에서만 알 수 있습니다.

고객 이름 칸에 아래 값을 하나씩 넣어 계약을 만들고, `Contracts` 시트의 `customerName` 칸을 봅니다.

| 넣을 값 | 통과 기준 |
| --- | --- |
| `=IMPORTXML("http://example.com","//a")` | **글자 그대로 보임.** 계산 결과나 `#ERROR!` 가 보이면 실패 |
| `=1+1` | `=1+1` 로 보임. `2` 가 보이면 **실패** |
| `+82 10-1234-5678` | 글자 그대로 보임 |
| `-강조-` | 글자 그대로 보임 |
| `@김사장` | 글자 그대로 보임 |
| **` =1+1`** (앞에 **공백 한 칸**) | ⚠ **이 항목이 이번에 확인해야 할 것입니다.** 아래 참고 |

#### ⚠ 앞에 공백이 있는 등호 — 확인이 필요합니다

`sheetSafe` 는 `=` `+` `-` `@` 와 탭·개행으로 **시작하는** 값만 막습니다.
`' =1+1'` 처럼 **일반 공백이 먼저 오면 막지 않습니다.**

구글시트가 앞 공백을 떼고 수식으로 읽는지 여부는 Node 검사로 알 수 없어
자동 검사에서는 “지금 동작”만 못박아 두었습니다(`[미확정]` 표시).

| 결과 | 뜻 | 하실 일 |
| --- | --- | --- |
| ` =1+1` 이 글자로 보임 | 괜찮습니다 | 없음 |
| `2` 로 계산됨 | **구멍입니다** | **즉시 알려 주세요.** `Pure.gs` 의 `FORMULA_LEAD` 를 고쳐야 합니다 |

#### ⚠ 작은따옴표로 시작하는 이름

고객 이름을 **`'김사장`** (앞에 작은따옴표)으로 넣고, 시트에 적힌 뒤 계약서 PDF 에 어떻게 찍히는지 보세요.

| 결과 | 뜻 |
| --- | --- |
| `'김사장` 그대로 | 정상 |
| `김사장` (따옴표 사라짐) | 알려진 한계입니다. 안전에는 문제없지만 이름이 달라집니다 |

> 이 두 가지는 자동 검사가 “확인 필요”로 표시해 둔 항목입니다.
> 실제 시트에서 한 번 확인하시면 그 뒤로는 다시 볼 필요 없습니다.

### B-4 잠금과 원본 PDF

계약을 잠급니다(`quickSend` 를 쓰셨다면 이미 잠겼습니다).

| 볼 곳 | 통과 기준 |
| --- | --- |
| `Contracts` | `status` 가 `LOCKED` · `docHash` 에 64자리 16진수 · `lockedAt` 에 시각 |
| Drive | `전자계약/MM-2026-XXXX 홍길동/원본_MM-2026-XXXX.pdf` 가 생김 |
| **PDF 를 열어서** | 아래 B-5 |

### B-5 ⛔ PDF 모양 — 눈으로만 알 수 있는 것

원본 PDF 를 열어 확인합니다. **자동 검사가 절대 못 보는 영역입니다.**

- [ ] 한글이 **네모(□□□)로 깨지지 않는가**
- [ ] 계약 제목·고객 이름이 잘리지 않는가
- [ ] 금액이 `1,234,567원` 처럼 쉼표와 함께 제대로 보이는가
- [ ] 계약금·중도금·잔금 표의 **합이 총액과 같게 찍혀 있는가**
- [ ] 조항 글이 페이지 밖으로 넘치지 않는가
- [ ] 표가 페이지 경계에서 어색하게 잘리지 않는가
- [ ] 보증기간(`방수 3년 · 급배수 등 설비 2년 · 그 밖의 마감 1년`)이 제대로 보이는가
- [ ] 사업자 정보(상호·대표·사업자번호·연락처)가 맞는가
- [ ] **고객 전화번호 원문이 PDF 에 찍혀 있지 않은가**

> 한글 깨짐은 특히 조심하세요. 구글의 HTML→PDF 변환은 글꼴에 따라 달라집니다.
> **인쇄해서 고객에게 드릴 문서**이므로 화면에서 보이는 것과 인쇄가 다를 수 있습니다 —
> 한 장 인쇄해 보세요.

## C. 폰에서 — 고객이 보는 화면

**사장님 폰으로 직접 하세요.** PC 브라우저의 모바일 보기로는 알 수 없는 것들입니다.

> ⛔ **A-7 에서 `modules.sign` 이 `false` 라면 이 장은 아직 못 합니다.**
> `Sign.gs` 를 붙여넣고 다시 배포한 뒤에 하세요.

### C-1 링크가 문자·카톡에서 안 잘리는가

| | |
| --- | --- |
| 어떻게 | 발급된 `signUrl` 을 **카톡으로 자기 자신에게** 보내고 눌러 봅니다 |
| 통과 | 링크 전체가 파랗게 잡히고, 눌렀을 때 서명 화면이 뜸 |
| 실패하면 | 링크가 중간에서 끊겼습니다. `?t=` 뒤가 다 갔는지 확인 |

문자(SMS)로도 한 번 보내 보세요. 문자는 길이 제한이 있어 잘릴 수 있습니다.

### C-2 ⛔ 폰에서 글자가 읽히는가

| | |
| --- | --- |
| 어떻게 | 폰에서 서명 링크를 엽니다 |
| 통과 | 글자가 **읽을 수 있는 크기**. 가로로 밀지 않아도 다 보임 |
| 실패하면 | 글자가 개미만 하면 `viewport` 문제입니다. 화면 사진을 찍어 알려 주세요 |

> 60대 고객이 보실 화면입니다. **사장님이 안경 없이 읽을 수 있어야** 통과입니다.

### C-3 ⛔ 손가락으로 서명이 그려지는가

- [ ] 손가락을 대고 그으면 **선이 따라 그려지는가**
- [ ] 선이 끊기거나 뚝뚝 끊어지지 않는가
- [ ] 손바닥이 화면에 닿아도 이상한 선이 안 그려지는가
- [ ] `지우기` 를 누르면 깨끗이 지워지는가
- [ ] 서명 칸을 그으려는데 **화면이 위아래로 스크롤되지 않는가** ← 자주 나는 문제
- [ ] 폰을 **가로로 돌렸다 세워도** 그린 서명이 남아 있는가
- [ ] 아무것도 안 그리고 제출하면 “서명이 비어 있습니다” 가 뜨는가
- [ ] 동의 체크를 안 하고 제출하면 막히는가

> 자동 검사는 “빈 서명을 막는다”는 규칙만 봅니다.
> **손가락이 실제로 그려지는지**는 사람만 알 수 있습니다.

### C-4 서명 제출 후 — 모든 것이 제자리에 생겼는가

| 볼 곳 | 통과 기준 |
| --- | --- |
| 고객 화면 | 완료 안내가 뜨고, 다시 새로고침하면 “이미 사용된 링크” 안내 |
| `Contracts` | `status` = `COMPLETED` · `signedAt`·`completedAt` 에 시각 · `signerName` 에 입력한 이름 |
| `Contracts` | `signatureSha256`·`completedSha256` 에 64자리 16진수 · `completedFileVersion` = 1 |
| Drive | `서명_MM-….png` · `완료_MM-…_v1.pdf` · `증거_MM-…_v1.json` 세 개가 생김 |
| `SignTokens` | 그 토큰 줄의 `usedAt` 에 시각이 찍힘 |
| `ContractEvents` | `SIGN_LINK_OPENED` · `SIGN_SUBMITTED` · `CONTRACT_COMPLETED` 가 **시간 순서대로** |

### C-5 완료본 PDF 에 서명이 제대로 들어갔는가

- [ ] 서명 그림이 **찌그러지거나 뒤집히지 않았는가**
- [ ] 서명이 서명란 안에 들어가 있는가 (밖으로 나가거나 잘리지 않았는가)
- [ ] 서명이 너무 흐리거나 너무 굵지 않은가
- [ ] 서명자 이름·서명 시각이 함께 찍혀 있는가
- [ ] 문서 지문(`docHash`)이 PDF 안에 적혀 있고 시트 값과 **같은가**

### C-6 증거 JSON 을 열어 보기

`증거_MM-…_v1.json` 을 열어:

- [ ] 서명 시각이 **서버 기준 시각**인가 (고객 폰 시계가 아님)
- [ ] `signatureSha256` 이 시트 값과 같은가
- [ ] 고객이 본 지문(`docHashSeen`)과 계약의 `docHash` 가 **같은가**
- [ ] ⛔ **전화번호 원문·토큰 원문이 들어 있지 않은가**
- [ ] IP 자리에 “Apps Script 웹앱은 요청자 IP 를 제공하지 않음” 이라고 **적혀 있는가**
      (빈칸이 아니라 이유가 적혀 있어야 나중에 오해가 없습니다)

## D. 안전 — 실제로 막히는지 시도해 보기

**막힌다고 적혀 있는 것을 직접 뚫어 보세요.** 안 뚫려야 통과입니다.

### D-1 ⛔ 다 쓴 링크를 다시 쓸 수 있는가

| | |
| --- | --- |
| 어떻게 | C-4 에서 서명을 마친 링크를 **다시** 엽니다 |
| 통과 | 서명 화면이 뜨지 않고 “이미 사용된 링크” 안내 |
| 실패하면 | 같은 계약에 두 번 서명할 수 있습니다. 즉시 알려 주세요 |

### D-2 ⛔ 토큰을 한 글자 바꾸면 열리는가

| | |
| --- | --- |
| 어떻게 | 링크 주소의 `?t=` 뒤 **마지막 글자 하나**를 다른 글자로 바꿔 엽니다 |
| 통과 | 열리지 않음 |
| 실패하면 | 즉시 알려 주세요 |

### D-3 ⛔ 계약 ID 로 고객이 열 수 있는가

| | |
| --- | --- |
| 어떻게 | `/exec?page=sign&t=ct_…` (시트에서 복사한 계약 `id` 를 토큰 자리에) |
| 통과 | 열리지 않음 |
| 실패하면 | **ID 를 찍으면 남의 계약이 열립니다.** 가장 심각한 실패입니다 |

### D-4 ⛔ 관리자 토큰 없이 관리자 화면이 되는가

| | |
| --- | --- |
| 어떻게 | `/exec?page=admin` 을 열고 **토큰을 넣지 않은 채** 목록을 눌러 봅니다 |
| 통과 | 아무것도 안 나오고 “권한 없음” 안내 |
| 실패하면 | 즉시 알려 주세요 |

토큰을 **한 글자 틀리게** 넣어도 안 되는지 확인하세요.
그리고 `ContractEvents` 에 `ADMIN_AUTH_FAILED` 가 남되 **토큰 값은 안 남아 있는지** 보세요.

### D-5 ⛔ 취소한 계약의 링크가 죽는가

| | |
| --- | --- |
| 어떻게 | 새 시험 계약 → 링크 발급 → **`voidContract` 로 취소** → 그 링크를 엽니다 |
| 통과 | 열리지 않음. `SignTokens` 의 그 줄에 `revokedAt` 이 찍힘 |
| 실패하면 | 취소한 계약에 서명이 들어올 수 있습니다 |

### D-6 만료된 링크가 죽는가

| | |
| --- | --- |
| 어떻게 | `SIGN_TTL_HOURS` 를 잠깐 `1` 로 두고 링크 발급 → **한 시간 뒤** 열어 보기 |
| 통과 | 열리지 않음 |
| 확인 후 | `SIGN_TTL_HOURS` 를 원래대로(지우거나 `72`) 되돌리세요 |

> 자동 검사는 `tokenState`·`isExpired` 로직을 봅니다.
> **실제 시각으로 정말 죽는지**는 시간을 들여야 알 수 있습니다.

### D-7 ⛔ 실행 로그에 비밀값이 안 찍히는가

| | |
| --- | --- |
| 어떻게 | 편집기 왼쪽 **`실행`** 을 열어 최근 실행 기록을 훑습니다. 오류가 난 실행도 열어 보세요 |
| 통과 | 관리자 토큰·PEPPER·고객 전화번호 원문·서명 링크 원문이 **한 글자도 없음** |
| 실패하면 | 어느 실행의 어느 줄인지 알려 주세요 |

`ContractEvents` 의 `detail` 열도 위에서 아래로 한 번 훑어 주세요. 같은 기준입니다.

### D-8 두 번 눌러도 계약이 두 건 생기지 않는가

| | |
| --- | --- |
| 어떻게 | 계약 만들기 버튼을 **빠르게 두 번** 누릅니다 |
| 통과 | `Contracts` 에 줄이 **하나만** 생김 |
| 실패하면 | 두 줄이 생기면 알려 주세요. 잘못 생긴 쪽은 `voidContract` 로 취소하시고 **지우지는 마세요** |

신호가 나쁜 곳(엘리베이터 앞·지하)에서 한 번 더 해 보시면 더 좋습니다.

## E. 정기 점검

### E-1 매일 자동 백업이 실제로 도는가 (설치 다음 날)

| | |
| --- | --- |
| 어떻게 | Drive `전자계약/백업/` 을 봅니다 |
| 통과 | `계약백업_2026….json` 이 **어제 날짜로** 생겨 있음 |
| 실패하면 | 편집기 왼쪽 ⏰ `트리거` 에 `dailyBackupJob` 이 있는지 확인. 없으면 `installDailyBackup` 실행 |

백업 파일을 열어 `counts` 의 숫자가 실제 시트 줄 수와 같은지 한 번 대조해 보세요.

### E-2 월 1회 — 눈으로 훑기

- [ ] `Contracts` 시트에 전화번호 원문이 없는가
- [ ] `ContractEvents` 의 `detail` 에 민감정보가 없는가
- [ ] `Settings` 시트에 비밀처럼 생긴 값이 없는가
- [ ] Drive `전자계약/` 아래에 **계약 건수만큼** 폴더가 있는가
- [ ] 완료된 계약마다 `완료_….pdf` 가 있는가
- [ ] 백업 폴더에 최근 파일이 쌓이고 있는가

### E-3 건수가 늘면 — 느려지는지 지켜보기

| | |
| --- | --- |
| 어떻게 | 계약 목록을 열 때 **몇 초 걸리는지** 재 봅니다 |
| 지켜볼 선 | 5초를 넘기 시작하면 알려 주세요 |
| 왜 | 시트 전체를 읽는 구조라 건수에 비례해 느려집니다. 6분 제한이 가까워지는 신호입니다 |

이 신호는 [SETUP.md 11장](./SETUP.md)의 “③ 건수가 늘 때”와 같은 뜻입니다.
