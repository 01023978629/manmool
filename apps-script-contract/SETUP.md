# 설치 안내서 — 혼자 따라 하실 수 있게

처음부터 끝까지 **한 시간이면 끝납니다.** 순서대로만 하세요.
화면에 보이는 글자를 그대로 적었습니다. 구글이 화면을 조금씩 바꾸므로
글자가 다르면 **뜻이 같은 것**을 누르시면 됩니다.

> **클릭 수 결정:** `clasp run-function` 자동실행은 별도 OAuth 자격증명, 표준 Google
> Cloud 프로젝트 연결, Apps Script API 실행 배포가 더 필요합니다. 그래서 계정 승인 뒤
> 편집기에서 `bootstrap()` 한 번을 실행하는 편이 실제 조작이 더 적고, 비밀값도 터미널로
> 되가져오지 않습니다.

## ⚠️ 시작하기 전에 — 가장 중요한 경고

### 지금 쓰고 계신 사진 중계 프로젝트에 **절대 넣지 마세요.**

현장 앱이 사진을 저장할 때 쓰는 Apps Script 프로젝트가 이미 하나 있습니다
(현장 앱 `☁️ 구글드라이브` 설정에 주소가 들어 있는 그것입니다).

**그 프로젝트에 이 파일들을 붙여넣으면 사진 중계가 망가집니다.**
Apps Script 는 한 프로젝트 안의 모든 파일이 이름을 함께 씁니다.
`doPost` 라는 이름이 양쪽에 있으므로, 한쪽을 붙여넣는 순간 다른 쪽이 조용히 덮어써집니다.
경고도 오류도 나지 않습니다. **사진이 저장되지 않는 것을 며칠 뒤에야 아시게 됩니다.**

> ### 반드시 **새 프로젝트**를 만드세요.
> 사진 중계 프로젝트는 **열지도 마세요.**

두 프로젝트를 구분하는 법:

| | 사진 중계 (기존, 손대지 마세요) | 전자계약 (지금 만드는 것) |
| --- | --- | --- |
| 프로젝트 이름 | 예: `만물 사진 릴레이` | `만물 전자계약` 으로 지으세요 |
| 현장 앱 설정 자리 | `☁️ 구글드라이브` | `📨 전자계약 서버 연결` |
| 배포 주소 | 이미 앱에 들어 있음 | 이번에 새로 나옵니다 |

## 1. 새 프로젝트 만들기

1. 브라우저에서 **script.google.com** 으로 갑니다.
   → 사장님의 구글 계정으로 로그인되어 있어야 합니다.
2. 왼쪽 위 **[+ 새 프로젝트]** 를 누릅니다.
3. 화면 맨 위 **`제목 없는 프로젝트`** 글자를 누르고 **`만물 전자계약`** 으로 바꿉니다.
   → 이름을 바꿔 두셔야 나중에 사진 중계와 헷갈리지 않습니다.

이제 왼쪽에 **`Code.gs`** 파일 하나만 있는 빈 프로젝트가 보입니다.

## 2. 파일 붙여넣기 — **이 순서대로**

Apps Script 는 파일을 위에서부터 이어 붙여 실행합니다.
순서가 틀리면 "없는 함수를 부른다"는 오류가 납니다.

### 2-1. 먼저 `.gs` 파일 (11개)

| 순서 | 파일 이름 (`.gs` 는 빼고 입력) | 이 저장소의 파일 |
| --- | --- | --- |
| 1 | `Pure` | `Pure.gs` |
| 2 | `Schema` | `Schema.gs` |
| 3 | `AuthService` | `AuthService.gs` |
| 4 | `SheetService` | `SheetService.gs` |
| 5 | `DriveService` | `DriveService.gs` |
| 6 | `ContractService` | `ContractService.gs` |
| 7 | `Sign` | `Sign.gs` |
| 8 | `Notify` | `Notify.gs` |
| 9 | `AiService` | `AiService.gs` |
| 10 | `MigrationService` | `MigrationService.gs` |
| 11 | `Code` | `Code.gs` ← **이미 있는 `Code.gs` 를 열어 내용을 통째로 바꿉니다** |

> ### 하나라도 빠뜨리면 그 기능만 조용히 없어집니다
> `Code.gs` 는 다른 파일의 함수를 **이름으로 찾아** 부릅니다. 없으면 오류가 나는 대신
> "그 모듈이 설치되지 않았습니다" 라고 정확히 답합니다 — 나머지는 계속 돕니다.
> `health` 응답의 `modules` 를 보면 어느 것이 빠졌는지 바로 보입니다
> (`sign` · `notify` · `ai`). **`modules.sign` 이 `false` 면 고객에게 링크를 보내지 마세요.**

새 파일 만드는 법:
왼쪽 **`파일`** 옆의 **`+`** → **`스크립트`** → 이름 입력 → `Enter`.

> 이름을 넣을 때 **`.gs` 는 빼고** 넣으세요. 구글이 알아서 붙입니다.
> `Pure.gs` 라고 넣으면 `Pure.gs.gs` 가 됩니다.

새로 만든 파일에는 이런 줄이 미리 들어 있습니다:

```
function myFunction() {

}
```

**전부 지우고**(`Ctrl+A` → `Delete`) 저장소 파일 내용을 붙여넣으세요.

### 2-2. 그다음 `.html` 파일 (2개)

| 파일 이름 (`.html` 은 빼고 입력) | 이 저장소의 파일 |
| --- | --- |
| `Sign` | `Sign.html` |
| `Admin` | `Admin.html` |

만드는 법: **`+`** → **`HTML`** → 이름 입력.
(HTML 파일도 기본 내용이 들어 있습니다. 전부 지우고 붙여넣으세요.)

### 2-3. 마지막으로 매니페스트

1. 왼쪽 톱니바퀴 **`프로젝트 설정`** 을 누릅니다.
2. **`"appsscript.json" 매니페스트 파일을 편집기에 표시`** 에 체크합니다.
3. 왼쪽 파일 목록에 `appsscript.json` 이 생깁니다. 열어서 저장소의 `appsscript.json` 내용으로 바꿉니다.

여기에 **권한 범위**(Sheets·Drive·외부요청·트리거)와 웹앱 설정이 들어 있습니다.
이걸 넣지 않으면 구글이 필요 이상의 권한을 물어보거나, 반대로 권한이 모자라 저장이 막힙니다.

### 2-4. 저장

**`Ctrl+S`** (맥은 `⌘+S`). 화면 위에 잠깐 `저장 중…` 이 뜨고 사라지면 된 것입니다.

## 3. 스프레드시트와 Drive 폴더 만들기

### 3-1. 스프레드시트

1. **sheets.google.com** → **`+ 빈 스프레드시트`**
2. 이름을 **`만물 전자계약 자료`** 로 바꿉니다.
3. 주소창을 봅니다:

```
https://docs.google.com/spreadsheets/d/1AbCdEfGhIjKlMnOpQrStUvWxYz1234567890/edit#gid=0
                                      └────────────── 이 부분이 ID ──────────────┘
```

`/d/` 와 `/edit` **사이의 긴 글자**가 ID 입니다. 복사해 두세요 → `SPREADSHEET_ID`

> 시트 안에 아무것도 만들지 마세요. 5장은 코드가 만듭니다(6장에서 합니다).

### 3-2. Drive 폴더

1. **drive.google.com** → **`+ 신규`** → **`새 폴더`**
2. 이름을 **`만물 전자계약`** 으로 합니다.
3. 그 폴더를 **두 번 눌러 들어간 뒤** 주소창을 봅니다:

```
https://drive.google.com/drive/folders/1ZyXwVuTsRqPoNmLkJiHgFeDcBa0987654321
                                       └──────────── 이 부분이 ID ────────────┘
```

복사해 두세요 → `DRIVE_FOLDER_ID`

> 이 폴더 **안에** 코드가 `전자계약/` 을 만들고, 그 안에 계약별 폴더를 만듭니다.
> 폴더 구조는 [README.md 3-2](./README.md) 를 보세요.

## 4. 스크립트 속성 넣기

**비밀값은 코드에 절대 적지 않습니다.** 여기에만 넣습니다.

Apps Script 편집기에서 왼쪽 톱니바퀴 **`프로젝트 설정`** →
아래로 내려 **`스크립트 속성`** → **`스크립트 속성 추가`**.

### 반드시 넣어야 하는 것 (4개)

| 속성 | 값 |
| --- | --- |
| `ADMIN_TOKEN` | 아래 4-1 에서 만듭니다 |
| `PEPPER` | 아래 4-1 에서 만듭니다 |
| `SPREADSHEET_ID` | 3-1 에서 복사한 값 |
| `DRIVE_FOLDER_ID` | 3-2 에서 복사한 값 |

### 넣어도 되고 안 넣어도 되는 것

| 속성 | 안 넣으면 | 언제 넣나 |
| --- | --- | --- |
| `WEBAPP_URL` | `quickSend` 가 **서명 링크 주소를 못 만듭니다**(계약과 토큰은 정상) | 7장에서 `/exec` 주소가 나온 뒤 |
| `SIGN_TTL_HOURS` | 72시간 | 링크 유효기간을 바꾸실 때 |
| `VIEW_TTL_MINUTES` | 15분 | 완료본 열람 시간을 바꾸실 때 |
| `ALIMTALK_LIVE` | **문자가 나가지 않습니다(기본)** | 카카오 승인이 끝난 뒤에만 |
| `SOLAPI_*` | 발송 안 함 | 실제 발송을 켤 때 |
| `GEMINI_API_KEY` | AI 는 **기기마다 넣은 키**로만 돕니다 | 아래 4-2 — 넣으시길 권합니다 |
| `OPENAI_API_KEY` | ChatGPT 안 씀 | **넣지 마세요**(유료). 아래 4-2 참조 |
| `AI_ALLOW_PAID` | ChatGPT 는 잠겨 있습니다(기본) | 유료를 정말 쓰기로 정하셨을 때만 `1` |

> ⚠️ `ALIMTALK_LIVE` 는 **지금 넣지 마세요.**
> 켜 두면 시험 삼아 만든 계약이 고객에게 진짜로 날아갑니다.
> `selfTest` 는 이것이 켜져 있으면 **실패**로 판정합니다. 일부러 그렇게 만들었습니다.

### 4-1. `ADMIN_TOKEN` 과 `PEPPER` 만드는 법

직접 만들거나 복사하지 않습니다. 편집기에서 먼저 `bootstrap(true)`를 실행해 계획을 보고,
그다음 `bootstrap()`을 실행합니다. 코드가 두 값을 각각 40자 이상으로 만들어 **스크립트
속성에만** 저장하며, 화면과 로그에는 값 대신 `설정됨`과 길이만 남깁니다. 다시 실행해도
기존 값, 특히 `PEPPER`를 덮어쓰지 않습니다.

### 4-2. AI 키를 여기에 넣으면 좋은 이유 (무료)

지금까지 Gemini 키는 **사장님 폰 브라우저 안**에 있었습니다. 그래서:

| 겪으시던 일 | 이유 |
| --- | --- |
| 기기마다 키를 또 넣어야 함 | 키는 보안상 클라우드 백업에 안 실립니다 |
| 며칠 지나면 키가 사라짐 | 사파리가 홈 화면에 없는 사이트의 저장소를 7일마다 정리합니다 |
| 한도가 두 배로 나감 | PC 200 + 폰 200 = 400건을 따로 셉니다 |

`GEMINI_API_KEY` 를 **여기 스크립트 속성**에 넣으면 셋 다 없어집니다.
기기에는 키가 아예 없어도 되고, 한도는 서버 한 곳에서 셉니다.

1. [`tools/install/gemini-key.md`](tools/install/gemini-key.md)의 auth key 절차를 따릅니다.
   2026년 9월 이후 Standard key 중단 예정 때문에 AI Studio Standard key를 새로 만들지 않습니다.
2. 스크립트 속성에 `GEMINI_API_KEY` 로 넣습니다.
3. 현장 앱 `⚙️ 설정` 을 열면 **"AI 키는 계약 서버에 있습니다"** 라고 뜹니다.
   안 뜨면 앱을 한 번 껐다 켜세요(부팅할 때 한 번만 물어봅니다).

> **ChatGPT(`OPENAI_API_KEY`) 는 쓰지 마시길 권합니다.** 쓴 만큼 요금이 붙고,
> OpenAI 키에는 도메인 제한 기능이 아예 없어 새면 막을 방법이 없습니다.
> 서버는 기본적으로 이것을 **잠가 둡니다** — 불러도 `AI_PAID_BLOCKED` 로 거절합니다.
> 정말 쓰시려면 `AI_ALLOW_PAID` 를 `1` 로 넣어야 열립니다. 현장 앱은 지금 Gemini 만 부릅니다.
>
> ⚠️ **다만 이 잠금이 요금 방어의 전부는 아닙니다.** `AI_ALLOW_PAID` 는 ChatGPT 에만 걸려 있어,
> Gemini 키의 프로젝트에 결제계정이 붙으면 **잠기지 않은 채로 과금됩니다.**
> 요금을 0 으로 만드는 것은 이 설정이 아니라 **결제계정을 붙이지 않는 것**뿐입니다.

### 두 값의 성격이 다릅니다 — 꼭 알아 두세요

| | `ADMIN_TOKEN` | `PEPPER` |
| --- | --- | --- |
| 무엇 | 사장님임을 증명하는 열쇠 | 전화번호를 가리는 비밀 재료 |
| 새는 날 | 남이 계약을 만들고 볼 수 있음 | 시트가 유출됐을 때 전화번호가 되찾아짐 |
| 바꿔도 되나 | **네.** 언제든 바꾸고 현장 앱에 다시 넣으면 됩니다 | **아니요.** 바꾸면 이미 저장된 전화번호 해시가 전부 무의미해집니다 |

> `PEPPER` 는 한 번 정하면 바꾸지 않습니다.
> 꼭 바꿔야 한다면 그건 설정 변경이 아니라 **자료 이관 작업**입니다.

## 5. 권한 승인 — "안전하지 않음" 경고 넘어가기

이 프로젝트는 사장님의 스프레드시트와 Drive 를 만집니다.
그래서 구글이 **한 번** 물어봅니다. 무섭게 생겼지만 정상입니다.

1. 화면 위 함수 고르는 칸에서 **`setupSheets`** 를 고릅니다.
2. **`▶ 실행`** 을 누릅니다.
3. **`승인 필요`** 창이 뜹니다 → **`권한 검토`**
4. 계정을 고릅니다(사장님 계정).
5. **여기가 그 화면입니다:**

> **이 앱은 Google에서 확인하지 않았습니다**
> 앱에서 Google 계정의 민감한 정보에 대한 액세스를 요청합니다.

6. 왼쪽 아래 작은 글씨 **`고급`** 을 누릅니다.
7. 아래에 나타나는 **`만물 전자계약(안전하지 않음)으로 이동`** 을 누릅니다.
8. 권한 목록이 나오면 맨 아래 **`허용`** 을 누릅니다.

### 이 경고가 왜 뜨나요 — 그리고 왜 넘어가도 되나요

구글은 **일반에 공개된 앱**만 심사합니다.
이건 사장님이 사장님 계정에서 직접 만든, 사장님만 쓰는 코드입니다.
심사 대상이 아니므로 "확인하지 않았다"고 뜨는 것이지, 위험하다는 뜻이 아닙니다.

**다만 이 경고는 진짜로 쓸모가 있습니다.** 남이 보낸 스크립트 링크에서 이 화면이 뜨면
절대 넘어가지 마세요. 지금은 사장님이 붙여넣은 코드라서 넘어가는 것입니다.

## 6. 시트 만들기와 자가진단

### 6-1. 시트 5장 만들기

5장에서 `setupSheets` 를 실행하셨으면 이미 만들어졌습니다.
아래 **`실행 로그`** 에 이렇게 나옵니다:

```
시트 준비: 만듦=Contracts,ContractEvents,Payments,SignTokens,Settings · 열추가=없음 · 어긋남=없음
```

스프레드시트를 열어 보시면 아래에 탭 5개가 생겨 있습니다.
**`어긋남`** 에 뭔가 적혀 있으면 멈추고 그 내용을 알려 주세요 — 열 순서가 맞지 않는다는 뜻입니다.

### 6-2. 자가진단

1. 함수 고르는 칸에서 **`runSelfTest`** 를 고르고 **`▶ 실행`**.
2. **`실행 로그`** 에 이렇게 나와야 합니다:

```
selfTest allOk = true
  [통과] 스크립트 속성 ADMIN_TOKEN — 설정됨
  [통과] 스크립트 속성 PEPPER — 설정됨
  [통과] 스크립트 속성 SPREADSHEET_ID — 설정됨
  [통과] 스크립트 속성 DRIVE_FOLDER_ID — 설정됨
  [통과] 스프레드시트 열림 — 시트 6장
  [통과] 시트 5개 존재 — 모두 있음
  [통과] Drive 폴더 열림 — 폴더 「만물 전자계약」
  [통과] PEPPER 해시 생성 — 정상(해시 값은 남기지 않습니다)
  [통과] 문자 발송 꺼짐 — 꺼져 있음(MOCK_OFF)
```

**`allOk = true`** 가 아니면 다음으로 넘어가지 마세요.
`[실패]` 줄에 무엇을 해야 하는지 적혀 있습니다.

## 7. 웹앱으로 배포하기

1. 오른쪽 위 파란 **`배포`** → **`새 배포`**
2. 왼쪽 톱니바퀴 **`유형 선택`** → **`웹 앱`**
3. 아래 세 칸을 이렇게 채웁니다:

| 칸 | 넣을 값 |
| --- | --- |
| **설명** | `전자계약 v1` (아무거나 좋습니다) |
| **다음 사용자 인증 정보로 실행** | **`나(사장님 이메일)`** |
| **액세스 권한이 있는 사용자** | **`모든 사용자`** |

4. **`배포`** → 주소가 나옵니다:

```
https://script.google.com/macros/s/AKfycb.................../exec
```

**이 주소를 복사해 두세요.** 이것이 `/exec` 주소입니다.

5. 스크립트 속성으로 돌아가 **`WEBAPP_URL`** 에 이 주소를 넣습니다.
   → 넣지 않으면 `quickSend` 가 서명 링크 주소를 만들지 못합니다.

### 왜 "모든 사용자" 여야 하나요 — 위험하지 않나요

**고객이 로그인 없이 서명해야 하기 때문입니다.**

`나만` 이나 `Google 계정이 있는 모든 사용자` 로 두면, 고객이 문자로 받은 링크를 눌렀을 때
구글 로그인 화면이 먼저 뜹니다. 60대 고객에게 "구글 계정으로 로그인하세요"라고 할 수는 없습니다.
로그인을 요구하는 순간 계약이 진행되지 않습니다.

**그럼 아무나 계약을 볼 수 있나요? 아닙니다.**

문이 열려 있는 것과 금고가 열려 있는 것은 다릅니다.
`/exec` 주소는 누구나 열 수 있지만, **토큰이 관문입니다**:

| 그냥 주소만 열면 | `?page=sign&t=<토큰>` 로 열면 |
| --- | --- |
| 안내 문구와 전화번호만 나옵니다 | 그 토큰에 딸린 계약 하나만 열립니다 |
| 계약 목록도, 동작 목록도 보여 주지 않습니다 | 72시간 지나면 죽습니다 |
| | 서명하면 그 자리에서 소진됩니다 |
| | 계약이 취소되면 함께 무효가 됩니다 |

- **관리자 동작**은 전부 `ADMIN_TOKEN` 을 대조합니다. 토큰이 없으면 아무것도 안 됩니다.
- **고객 동작**은 서명 토큰만 받습니다. **계약 ID 로는 고객이 아무것도 열 수 없습니다** —
  ID 를 찍어서 맞혀도 남의 계약이 열리지 않습니다.
- 토큰은 32바이트 무작위입니다. 찍어서 맞힐 수 있는 값이 아닙니다.
- 서버에는 토큰의 **해시만** 있습니다. 시트가 통째로 유출돼도 링크를 만들 수 없습니다.

### `실행: 나` 인 이유

코드가 **사장님 계정의 권한으로** 스프레드시트와 Drive 에 씁니다.
`사용자` 로 두면 고객이 서명할 때 고객의 Drive 에 쓰려고 해서 실패합니다.

> **코드를 고칠 때마다 `배포` → `배포 관리` → 연필(수정) → `버전: 새 버전` → `배포`** 를 해야
> 바뀐 코드가 반영됩니다. 저장(`Ctrl+S`)만으로는 배포된 주소가 바뀌지 않습니다.
> 이 방법으로 하면 **주소가 그대로 유지**됩니다(`새 배포` 를 누르면 주소가 바뀝니다).

## 9. 백업·복구, 토큰 재설정

### 9-1. 매일 자동 백업 켜기

`bootstrap()`이 같은 이름의 트리거가 없을 때 자동으로 설치합니다. 별도 실행은 필요 없습니다.

- 매일 **새벽 3시대**에 전체를 JSON 으로 `전자계약/백업/` 에 저장합니다.
- 파일 이름: `계약백업_20260730-0300.json`
- 트리거 확인: 왼쪽 ⏰ **`트리거`** 에서 `dailyBackupJob` 이 보이면 된 것입니다.
- 한 번만 실행하면 됩니다. 두 번 실행해도 트리거가 두 개 생기지 않습니다.

### 9-2. 손으로 백업하기

현장 앱이나 관리자 화면(`/exec?page=admin`)에서 **`backup`** 을 실행하면 그 자리에서 만듭니다.
중요한 계약을 끝낸 날은 손으로 한 번 더 눌러 두세요.

### 9-3. 복구 — 무엇이 되고 무엇이 안 되나

| 잃은 것 | 복구 방법 |
| --- | --- |
| 시트 한 줄을 잘못 고침 | 스프레드시트 **`파일` → `버전 기록` → `버전 기록 보기`** 에서 되돌립니다. 구글이 자동으로 남깁니다 |
| 시트 전체 | 백업 JSON 의 `sheets` 를 보고 다시 넣습니다. 건수·금액 합계가 함께 들어 있어 대조할 수 있습니다 |
| 계약 PDF·서명 이미지 | Drive **휴지통**을 보세요. 코드는 파일을 지우지 않습니다 — 지웠다면 사람이 지운 것입니다 |
| 스프레드시트를 통째로 삭제 | Drive 휴지통 → 복원. 그다음 `SPREADSHEET_ID` 가 그대로인지 확인 |

> **백업 JSON 을 다른 사람에게 보내지 마세요.** 고객 이름·마스킹 번호·계약 금액이 들어 있습니다.

### 9-4. 관리자 토큰 재설정 (`ADMIN_TOKEN` 이 샜다고 생각되실 때)

1. 4-1 의 방법으로 **새 값**을 만듭니다.
2. `프로젝트 설정` → `스크립트 속성` → `ADMIN_TOKEN` 의 값을 **바꿔서 저장**합니다.
3. **이 순간부터 옛 토큰은 통하지 않습니다.** 다시 배포할 필요 없습니다.
4. 현장 앱 `📨 전자계약 서버 연결` 에서 새 토큰을 넣고 **`💾 저장` → `🩺 자가진단`**.
5. 사장님이 쓰시는 **모든 기기**에서 4번을 반복하세요(폰·태블릿·PC).

> **고객 서명 링크는 영향받지 않습니다.** 그건 다른 종류의 토큰입니다.
> 이미 나간 링크는 그대로 살아 있습니다.

### 9-5. `PEPPER` 는 재설정하지 마세요

바꾸는 순간 이미 저장된 전화번호 해시가 전부 무의미해집니다(대조 불가).
꼭 바꿔야 한다면 옛 값으로 전부 다시 계산해 넣는 이관 작업이 필요합니다. 혼자 하지 마세요.

## 10. 무료 사용량 한도와 장애 대응

### 확실히 아는 것

- **실행 한 번에 6분**입니다. 넘으면 구글이 그 자리에서 끊습니다.
  이건 오래된 제한이고 바뀌지 않았습니다.

### 제가 확실히 알지 못하는 것 — **추측한 숫자를 여기 적지 않았습니다**

아래 항목에도 **한도가 있습니다.** 하지만 정확한 수치는 계정 종류(개인 Gmail / Workspace)와
시기에 따라 달라지고, 저는 지금 시점의 정확한 값을 확신하지 못합니다.

- 하루 총 스크립트 실행 시간
- 하루 `UrlFetch`(외부 요청) 호출 수
- 하루 트리거 총 실행 시간
- 하루 이메일 발송 수

**정확한 수치는 반드시 공식 문서에서 확인하세요:**

> **https://developers.google.com/apps-script/guides/services/quotas**

이 표는 구글이 직접 갱신합니다. 제가 여기 숫자를 적어 두면 언젠가 틀린 값이 되고,
사장님은 틀린 값을 믿고 계획을 세우시게 됩니다. 그래서 적지 않았습니다.

### 한도에 걸리면 어떻게 되나

| 증상 | 뜻 | 하실 일 |
| --- | --- | --- |
| `Exceeded maximum execution time` | 실행 6분 초과 | 백업·이전은 **다시 실행**하면 이어서 합니다(이미 넣은 줄은 건너뜁니다) |
| `Service invoked too many times` | 하루 호출 한도 초과 | **다음 날 자정(태평양 시간)에 초기화됩니다.** 그날은 계약을 걸지 마세요 |
| `BUSY` 응답 | 다른 작업이 잠금을 잡고 있음 | 20초 기다렸다가 다시 누르세요. **두 번 눌러도 계약이 두 건 생기지 않습니다**(멱등) |
| 응답이 없음 / 시간 초과 | 구글 쪽 장애 | 잠시 뒤 다시. 실패한 요청은 **성공으로 기록되지 않습니다** |

### 장애가 났을 때 지켜야 할 것

1. **`ok` 를 보지 않고 "보냈습니다"라고 넘어가지 마세요.**
   응답의 `ok` 가 `false` 면 실패입니다. HTTP 상태는 언제나 200 이라 상태코드로는 알 수 없습니다.
2. **`notify.sent` 가 `false` 여도 계약과 링크는 정상입니다.**
   문자만 안 나간 것이니 링크를 직접 카톡으로 보내시면 됩니다.
3. **계약이 두 건 생긴 것 같으면** 관리자 화면에서 목록을 확인하고,
   잘못 생긴 쪽을 `voidContract` 로 취소하세요. **지우지 마세요** — 원장에 흔적이 남아야 합니다.
4. **막혔을 때 코드를 고치려 하지 마세요.** 무엇을 눌렀고 화면에 뭐라고 나왔는지 알려 주세요.

### 지금 규모에서 걱정하지 않으셔도 되는 이유

1인 시공, 연 수십 건입니다. 계약 한 건에 드는 실행 시간은 몇 초이고,
문자 발송은 아직 꺼져 있어 `UrlFetch` 를 거의 쓰지 않습니다.
**한도가 문제가 되는 시점은 아래 11장의 "옮길 때"와 거의 같습니다.**

## 11. 언제 Supabase 로 옮겨야 하나

지금 구조는 **의도적으로 작게** 만들었습니다. 작아서 좋은 점이 있고, 작아서 아쉬운 점이 있습니다.
아래 중 **하나라도** 해당되면 옮길 때입니다.

### 옮길 때를 알리는 신호 세 가지

| 신호 | 왜 이때인가 |
| --- | --- |
| **① 사람이 늘 때** — 직원이나 파트너가 함께 계약을 만듦 | 지금은 `ADMIN_TOKEN` **하나**를 나눠 쓰는 구조입니다. 누가 만들었는지 구분되지 않고, 한 사람이 그만두면 전원이 토큰을 바꿔야 합니다. 계정별 권한이 필요해집니다 |
| **② 강한 본인확인이 필요할 때** — 금액이 커지거나 분쟁을 겪으심 | 지금은 링크를 받은 사람이 곧 서명자입니다. IP 도 못 남깁니다. 문자 OTP·신분증 대조 같은 절차가 필요하면 서버가 있어야 합니다 |
| **③ 건수가 늘 때** — 계약이 수백 건을 넘고 목록이 느려짐 | 시트 전체를 읽는 구조라 건수에 비례해 느려집니다. 6분 제한도 가까워집니다 |

### 지금 무엇이 아쉬운가 (정직하게)

| 아쉬운 것 | 지금 상태 |
| --- | --- |
| 고객 IP 증거 | **없습니다.** Apps Script 가 주지 않습니다 |
| 본인확인 | **없습니다.** 링크 소지 = 서명 자격 |
| 실행 시간 | 1회 6분 |
| 조회 속도 | 시트 전체 읽기. 수백 건부터 체감됩니다 |
| 동시성 | 잠금 하나로 줄 세움. 못 잡으면 실패 |
| HTTP 상태코드 | 언제나 200. `ok` 로만 구분 |
| 계정별 권한 | 토큰 하나뿐 |

### 옮기면 무엇이 달라지나

| | 지금 (Apps Script) | Supabase 로 옮기면 |
| --- | --- | --- |
| 비용 | **0원** | 무료 구간이 있지만 규모가 커지면 유료. 매달 나갑니다 |
| 서버 관리 | 없음 | 스키마·마이그레이션·키 관리가 생깁니다 |
| 고객 IP | 못 남김 | **남길 수 있습니다** |
| 본인확인 | 없음 | 문자 OTP·이메일 인증을 붙일 수 있습니다 |
| 실행 시간 | 6분 | 제한 없음(Edge Function 은 별도 제한) |
| 조회 속도 | 전체 읽기 | 인덱스 — 수만 건도 즉시 |
| 동시성 | 잠금 하나 | DB 트랜잭션 |
| 계정별 권한 | 없음 | 사용자별 권한(RLS) |
| 자료를 눈으로 보기 | **스프레드시트를 그냥 열면 보임** | 관리 화면이나 SQL 이 필요합니다 |
| 되돌리기 | 시트 버전 기록으로 손쉽게 | 백업 복원 절차가 필요합니다 |

### 옮기실 때 지켜야 할 것

- **지금 구조를 버리지 마세요.** `Pure.gs` 의 금액·상태·검증 규칙과 `Schema.gs` 의 열 정의는
  그대로 옮길 수 있게 만들어 두었습니다. Fly → Apps Script 로 올 때 그 규칙을 그대로 가져왔고,
